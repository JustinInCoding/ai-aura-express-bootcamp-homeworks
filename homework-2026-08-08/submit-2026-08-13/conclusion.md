# PUBG 胜负预测项目 — 学习总结（conclusion.md）

> 本项目使用机器学习回归模型，根据每局比赛 54 个特征预测玩家的最终排名百分位 `winPlacePerc`（0~1，越大排名越靠前）。
> 本文面向机器学习初学者，按「做了什么 → 为什么这么做 → 学到了什么」整理。

---

## 1. 项目目标与达标线

| 指标 | 目标 | 最终结果（随机森林） | 是否达标 |
|------|------|---------------------|----------|
| R²（决定系数） | > 0.925 | **0.9489** | ✅ |
| MAE（平均绝对误差） | < 0.059 | **0.0504** | ✅ |

> R² 越接近 1 越好（1 = 完美预测，0 = 相当于用均值瞎猜）；MAE 越小越好（预测值与真实值的平均绝对差距）。

---

## 2. 完整流程一览

```
加载数据 → 探索分析 → 数据清洗 → 特征工程 → 划分数据集
        → 基线模型 → 超参数调优 → 最终模型 → 评估 → 特征重要性分析
```

每一步的目的：

| 阶段 | 做了什么 | 解决什么问题 |
|------|----------|--------------|
| 探索分析 | `info()` / `describe()` / 直方图 / 箱线图 | 了解数据规模、缺失值、分布形状 |
| 数据清洗 | 特殊缺失值、删 Id、合并 matchType、Winsorize | 处理脏数据，让模型学得更稳 |
| 特征工程 | 队伍聚合特征 + 4 个新特征 | 把原始信息变成更有预测力的特征 |
| 划分数据集 | 训练 50 万 / 验证 88.9 万 | 用一部分训练、一部分独立评估 |
| 基线模型 | 默认参数随机森林 / 决策树 | 先有个基准分数，再谈优化 |
| 超参数调优 | RandomizedSearchCV 随机搜索 | 自动找更好的参数组合 |
| 特征重要性 | `feature_importances_` | 回答"什么因素决定胜负" |

---

## 3. 每个阶段的关键知识点

### 3.1 数据探索（pandas 基本功）
- `df.shape`：数据规模（行, 列）
- `df.info()`：每列名称、类型、非空数量、内存
- `df.describe()`：数值列的均值/标准差/分位数
- `value_counts()`：类别列各取值出现次数
- 直方图看分布，箱线图看异常值

### 3.2 数据清洗
- **特殊缺失值**：PUBG 里 `rankPoints == -1` 代表"未定级"，用 `df.loc[掩码, 列] = np.nan` 转成缺失值
- **删无用列**：`Id` 只是行号，对预测无意义
- **合并低频类别**：把 10+ 种 matchType 合并成 6 个常见模式 + `other`，减少独热编码后的列数
- **Winsorize（截断异常值）**：对 `damageDealt`、`longestKill` 等长尾连续列，用箱线图法则（Q1−1.5×IQR 到 Q3+1.5×IQR）把极端值"夹"回边界内，避免极端样本干扰训练

### 3.3 特征工程（最有价值的部分）
- **独热编码 One-Hot**：`pd.get_dummies(columns=['matchType'], drop_first=True)`，把文字类别变成 0/1 列；`drop_first=True` 去掉第一列避免冗余
- **队伍聚合特征**：用 `groupby(['matchId','groupId']).transform('sum')` 算出"我队伍的总伤害/总击杀"等 13 列，因为**团队表现是个人排名的强信号**
- **4 个新特征**：
  - `totalDistance` = 步行+载具+游泳距离（移动积极性）
  - `killEfficiency` = 击杀数 ÷ 伤害量（补刀效率，+1 防除零）
  - `teamContribution` = 助攻 + 扶起数（团队贡献）
  - `survivalScore` = (治疗+能量) ÷ (击杀+击倒+1)（生存续航 vs 战斗烈度）
- **`_missing` 缺失指示特征**：把"是否缺失"本身变成 0/1 特征——未定级玩家本身就是一种信息

### 3.4 数据划分
- `train_test_split(test_size=0.2, random_state=42)`：固定随机种子保证可复现
- 训练集子采样到 50 万（内存/时间限制），**验证集保留完整 88.9 万**——验证集越大评估越可靠
- 树模型（随机森林/决策树）对数据量大不敏感，50 万样本已足够

### 3.5 基线模型
- `RandomForestRegressor(n_estimators=100)`：100 棵决策树投票平均
- `DecisionTreeRegressor()`：单棵决策树，默认不限制深度
- 结果：随机森林明显优于单棵决策树（集成学习的力量）

### 3.6 超参数调优（RandomizedSearchCV）
- 核心概念：超参数 = 训练前由人设定的参数（树的数量、深度、叶子大小…），不是模型自己学出来的
- `RandomizedSearchCV`：从参数空间随机抽组合 → 每组 3 折交叉验证打分 → 挑最优
- 关键超参数含义：
  - `n_estimators`：树的数量（越多越稳，但边际收益递减）
  - `max_depth`：树的最大深度（限制深度 = 防过拟合）
  - `min_samples_leaf`：叶子最少样本数（越大树越简单）
  - `max_features`：每棵树分裂时随机抽几个特征（sqrt/log2 → 增强多样性）
  - `ccp_alpha`：剪枝强度（越大剪得越狠，决策树专用）
- **调参要用子样本**：在 5 万样本上搜索（快），找到的参数再用全量训练，速度提升约 10 倍

### 3.7 最终模型与评估
- 用 `best_params_` + `**` 展开字典创建最终模型
- 评估要同时看训练集和验证集：
  - 训练 R² 高、验证 R² 低 → **过拟合**（背答案，泛化差）
  - 两者都低 → **欠拟合**（容量不够）
- `cross_validate` 一次跑 5 折交叉验证，同时拿 R² 和 MAE 的均值±标准差

### 3.8 特征重要性（回答"什么决定胜负"）
- `model.feature_importances_`：树模型自带重要性分数（越大越重要）
- 按游戏机制分类汇总后，**移动活动（约 29%）> 团队/队伍（约 25%）> 战斗能力（约 15%）**
- 结论：跑图积极、持续移动、团队协作好的玩家，排名普遍更高

## 4. 实验结果对比

| 阶段 | 模型 | 训练集 R² | 验证集 R² | 验证集 MAE | 训练时间 |
|------|------|-----------|-----------|------------|----------|
| 基线 | 随机森林 | 0.9931 | 0.9509 | 0.0490 | 419s |
| 基线 | 决策树 | ≈1.0000 | 0.8973 | 0.0690 | 23s |
| 调优 | 随机森林 | 0.9854 | **0.9489** | **0.0504** | 54s |
| 调优 | 决策树 | 0.9249 | 0.9229 | 0.0619 | 23s |

**几个重要发现：**
1. 随机森林调优后验证 R² 只降了 0.002（0.9509 → 0.9489），但训练时间从 7 分钟降到 1 分钟——用极小精度换巨大速度，很划算
2. 调优后训练-验证差距从 0.042 收窄到 0.036 → **过拟合更轻**
3. 决策树训练-验证差距仅 0.002 → 不是过拟合，是**容量不足**（单棵树学不到更多规律），说明它在强噪声赛局数据上的上限约 0.92
4. 随机森林 vs 决策树：集成学习显著胜出（0.9489 vs 0.9229）

---

## 5. 踩过的坑（宝贵经验）

1. **巨型树拖垮训练**：搜索空间里若有 `max_depth=None`（不剪枝）+ 500 棵树 + 全特征这种"病态组合"，单次拟合 10-30 分钟，一次调参能跑 88 分钟。**教训**：调参前先约束搜索空间（树数≤300、深度≤25、特征子集），既省时间结果也差不多
2. **验证集大于训练集不是问题**：本数据 444 万行，训练 50 万 + 验证 89 万，两者都够用，验证集大反而评估更稳。"训练集 > 验证集"只是小数据集的经验法则
3. **matplotlib 中文乱码**：默认字体不含中文，需设置 `plt.rcParams['font.sans-serif'] = ['Arial Unicode MS', 'PingFang SC', ...]` 和 `axes.unicode_minus = False`；**注意如果某个 cell 单独重跑，要确保字体配置 cell 也跑过**
4. **调参要在子样本上做**：全量调参会慢得不可接受，先缩小样本找方向，再全量训练
5. **交叉验证双跑耗时翻倍**：`cross_val_score` 跑两遍（R²、MAE 各一遍）是 10 折；用 `cross_validate` 一次跑完双指标，快一半

## 6. 概念速查表

| 概念 | 一句话解释 |
|------|-----------|
| R² | 模型解释了数据多少方差，1 最好，0 等于瞎猜 |
| MAE | 预测值和真实值平均差多少，越小越好 |
| 训练集/验证集 | 训练集教模型，验证集考模型（考卷不能提前见过） |
| 过拟合 | 模型把训练数据背下来了，换新数据就拉胯 |
| 交叉验证 | 把训练数据切成几份轮流当验证集，评估更稳 |
| 随机森林 | 很多决策树各自乱猜再投票，比单棵树准得多 |
| 超参数调优 | 自动试不同参数组合，找验证分数最高的一组 |
| 独热编码 | 把"模式"这种文字变成模型能吃的 0/1 数字 |
| Winsorize | 把极端异常值夹回合理范围，防止带偏模型 |
| 特征重要性 | 模型自报"哪个特征对我预测帮助最大" |

---

## 7. 总结

本项目完整走了一遍机器学习回归的**标准流水线**：探索 → 清洗 → 特征工程 → 建模 → 调参 → 评估 → 解释。最终随机森林 **Val R² = 0.9489、MAE = 0.0504**，双达标。

三个最重要的收获：
1. **特征工程 > 调参**：队伍聚合特征和移动类特征带来的提升，远大于反复调参的收益
2. **集成学习很强大**：随机森林对单棵决策树是碾压式的优势
3. **工程意识很重要**：子采样调参、约束搜索空间、固定随机种子、释放内存、`cross_validate` 一次跑双指标——这些"省时间省内存"的技巧让大项目能跑得动、结果可复现

下一步可以尝试：`XGBoost` / `LightGBM`（更强的梯度提升树）、对 `team_*` 特征做更多组合、或者把 50 万训练集扩到 100 万看分数是否回升。

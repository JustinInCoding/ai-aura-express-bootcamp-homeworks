# PUBG 玩家排名预测 — 机器学习分析计划 (Plan)

## 1. 任务概述

使用 PUBG 数据集（`data/train_V2.csv`），构建机器学习模型预测玩家在比赛中的排名百分位 **`winPlacePerc`**（1 = 第一名，0 = 最后一名）。使用 80/20 split 划分训练集和验证集进行评估。

**核心目标**：

- 模型评估指标：**R² Score > 0.925**，**MAE < 0.059**
- 使用 Jupyter Notebook 完成全部分析

**运行环境**：

- Conda 环境：`machine-learning-aura`
- Notebook 文件：`pubg-analysis.ipynb`

---

## 2. 算法选择

### 方案 A：随机森林（Random Forest）【主力模型】

| 维度 | 理由 |
|------|------|
| **非线性建模能力** | 自动拟合特征与 winPlacePerc 之间的复杂非线性关系，无需手动构造交互项 |
| **鲁棒性** | 对异常值和缺失值不敏感，PUBG 数据中存在大量极端值（如 longestKill 因击倒后远离而失真），随机森林天然容忍 |
| **特征重要性** | 内置 `feature_importances_`，可直接输出各特征对预测的贡献度排序，完美支撑"哪些因素对获胜最重要"的结论 |
| **过拟合控制** | 集成多棵决策树，通过 Bagging + 随机子空间有效抑制过拟合 |
| **适用场景** | 表格型结构化数据，特征维度适中（~40 维），样本量大（数百万行），是最适合的主力模型 |

### 方案 B：决策树（Decision Tree）【对比模型】

| 维度 | 理由 |
|------|------|
| **可解释性** | 可对单棵树做可视化，直观展示 split 路径和阈值，帮助理解哪些特征在哪些区间最关键 |
| **对比价值** | 与随机森林是"单棵 vs 集成"的关系。通过对比两者在相同预处理下的表现，可直接量化 Bagging 集成的增益 |
| **调试能力** | 决策树容易过拟合——如果它在训练集远好于验证集，说明需要剪枝或深度限制；如果随机森林更好，说明集成确实带来了泛化提升 |
| **baseline 意义** | 决策树可作为清晰的基线，观察超参数优化后模型提升的空间 |

> ⚠️ **线性回归暂不采用**：PUBG 数据特征与 winPlacePerc 的关系高度非线性（如 kills=0 和 kills=10 对排名的影响不是线性比例），线性回归难以捕捉这些关系，且目标 score 0.925 对其难度过大。

## 3. 数据预处理方案（4 项）

### 3.1 特殊缺失值清洗

根据数据说明，存在以下需要特殊处理的"隐式缺失值"：

| 规则 | 操作 |
|------|------|
| `rankPoints == -1` | 将 `rankPoints` 替换为 `NaN`（-1 代表 None） |
| `rankPoints != -1` 且 `killPoints == 0` | 将 `killPoints` 替换为 `NaN` |
| `rankPoints != -1` 且 `winPoints == 0` | 将 `winPoints` 替换为 `NaN` |

处理完后再统一对缺失值做中位数填充（`SimpleImputer(strategy='median')`）。

### 3.2 无关特征剔除

移除对预测无帮助或泄漏标签信息的列：

- **`Id`**：玩家唯一标识，无预测意义
- **`groupId`** / **`matchId`**：本身无预测价值，但**暂时保留**——用于构造队伍/比赛聚合特征（PUBG 中同队玩家排名高度相关，队伍整体表现是个人排名的强信号），聚合完成后一并移除

### 3.3 matchType 类别特征编码

`matchType` 是字符串型类别特征，包含以下标准模式：

- `solo`, `duo`, `squad`（第三人称）
- `solo-fpp`, `duo-fpp`, `squad-fpp`（第一人称）
- 其他 event/custom 模式

使用 **One-Hot Encoding**（`pd.get_dummies`）将 matchType 转换为哑变量。将频率极低的 event 模式合并为 `other` 类别以减少稀疏性。

### 3.4 数值特征异常值处理

使用 **IQR（四分位距）法** 对每个数值特征检测异常值：

```
lower_bound = Q1 - 1.5 × IQR
upper_bound = Q3 + 1.5 × IQR
```

对超出边界的值做 **Winsorize 截尾**（替换为边界值），而非直接删除，保留样本量。仅对**连续长尾特征**截尾，重点关注：

- `longestKill`：可能因击倒后开车远离而异常放大
- `damageDealt`：作弊者可能产生极端值
- `walkDistance` / `rideDistance` / `swimDistance`：极端值可能为数据错误

**离散计数特征（`kills`、`DBNOs`、`heals`、`boosts` 等）不截尾**：树模型对离群值不敏感，截断反而会损失 `kills >= 3` 的有效信号。

## 4. 特征工程方案（队伍/比赛聚合特征 + 4 项基础特征）

### 4.1 队伍/比赛聚合特征（关键提升）

PUBG 是团队游戏：同队玩家的最终排名高度相关，且比赛参与人数直接决定排名百分位的分母。构造以下聚合特征（在 2.2 保留 `groupId`/`matchId` 的基础上）：

- **队伍级聚合**（按 `matchId + groupId` 分组，`sum`）：
  - `team_damageDealt` / `team_kills` / `team_heals` / `team_boosts` 等 13 列
- **`playersInGroup`**：队伍人数（solo=1 / duo=2 / squad=4，含队友掉线情况）
- **`playersInMatch`**：比赛参与人数（与 `winPlacePerc` 强相关）
- **`matchTotalKills`**：全场总击杀
- **`killPlaceRatio`**：`killPlace / playersInMatch`（相对击杀位置）

聚合完成后移除 `groupId`、`matchId`。

### 4.2 总移动距离

```
totalDistance = walkDistance + rideDistance + swimDistance
```

反映玩家的地图活动范围。跑图积极、搜索更多资源的玩家通常排名更高。

### 4.3 击杀效率

```
killEfficiency = kills / (damageDealt + 1)
```

表示"每造成多少伤害能拿到一个人头"的效率指标。高效率意味着枪法精准、不浪费子弹；低效率可能是伤害打足但人头被队友收掉（混助攻）。

### 4.4 团队贡献度

```
teamContribution = assists + revives
```

反映玩家在团队中的支援能力。特别是 revives（扶队友）在 squad/duo 模式中直接影响团队存活人数和最终排名。

### 4.5 生存能力指标

```
survivalScore = (heals + boosts) / (kills + knockouts + 1)
```

该比值反映"防守 vs 进攻"风格：值大意味着偏生存/苟分玩法（频繁回血回能量但击杀少），值小意味着偏激进刚枪。分析这种风格差异对排名的影响。

## 5. 模型训练与评估策略

### 5.1 数据划分

- 从 `train_V2.csv` 中按 **80/20 比例** 拆分训练集和验证集
- 使用 `train_test_split(random_state=42)` 确保可复现
- 训练集用于模型拟合，验证集用于调参和选模型
- 最终用验证集评估模型性能

### 5.2 特征与标签

- **特征 X**：除 `winPlacePerc`, `Id`, `groupId`, `matchId` 外的所有处理后的特征（`groupId`/`matchId` 在聚合特征构造完成后移除）
- **标签 y**：`winPlacePerc`

### 5.3 评估指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **R² Score** | > 0.925 | 衡量模型对排名方差解释的比例，越接近 1 越好 |
| **MAE** | < 0.059 | 平均绝对误差，直观反映预测排名与实际排名的差距 |

两个指标互为补充：R² 高说明整体趋势捕捉好，MAE 低说明单点预测偏差小。

### 5.4 超参数优化

对两个模型分别使用 **RandomizedSearchCV**（随机搜索）先快速锁定大范围，再用 **GridSearchCV**（网格搜索）在小范围内精调。

#### 随机森林超参数搜索空间

| 超参数 | 搜索范围 | 含义 |
|--------|----------|------|
| `n_estimators` | [100, 200, 300] | 树的数量 |
| `max_depth` | [10, 15, 20, 25] | 最大深度 |
| `min_samples_split` | [2, 5, 10, 20] | 内部节点最小样本数 |
| `min_samples_leaf` | [2, 5, 10] | 叶子节点最小样本数 |
| `max_features` | ['sqrt', 'log2'] | 每棵树随机采样的特征数 |

#### 决策树超参数搜索空间

| 超参数 | 搜索范围 | 含义 |
|--------|----------|------|
| `max_depth` | [10, 15, 20, 25] | 最大深度 |
| `min_samples_split` | [2, 5, 10, 20] | 内部节点最小样本数 |
| `min_samples_leaf` | [1, 2, 5, 10] | 叶子节点最小样本数 |
| `criterion` | ['squared_error', 'absolute_error'] | 分裂准则 |
| `ccp_alpha` | 动态网格（对数空间 8 个值，下限取 25 分位） | 成本复杂度剪枝，控制树复杂度、抑制过拟合 |

> 调参在 50 万样本基础上进一步子采样（随机森林约 5 万、决策树约 5 万）。`ccp_alpha` 网格下限取 25 分位而非最小值，避免近零 alpha（几乎不剪枝）配合深树产生巨型树拖垮调参。决策树采用「留足容量 + `ccp_alpha` 剪枝」的组合：深树配合剪枝可同时兼顾拟合度与泛化。调参后按最优参数在训练集上重新训练最终模型。

> 决策树实测最终模型（深度 25 / 叶最小 10 / `ccp_alpha≈3.9e-6`）：Train R² 0.9249 / Val R² 0.9229，MAE 0.0619。训练-验证差距仅 0.002，说明是**容量不足**而非过拟合——单棵树在强噪声的赛局数据上的拟合上限约 0.92，作为对照模型（体现"单棵 vs 集成"的差距）定位成立。

> 随机森林调参同样需要约束搜索空间：实测含 `n_estimators=500`、`max_depth=None`（不剪枝）、`max_features=None`（全特征）、`min_samples_leaf=1/2` 的 40 组合 × 3 折搜索耗时 **88 分钟**，且选出的正是巨型树参数（会进一步拖垮全量训练与内存）。故收紧空间（树数≤300、深度≤25、叶最小样本≥2、特征子集 sqrt/log2）并减至 25 组合 × 3 折，预计 5-10 分钟；随机森林对树数与深度边际收益递减，约束后的 `best_params_` 泛化差距可忽略。

> 搜索空间已排除巨型树组合，随机森林最终模型直接采用调参最优参数（`best_params_`，实测为 100 棵树 / 深度 25 / sqrt 特征 / 叶最小 2）在全量 50 万样本上训练，约 1 分钟、内存安全，无需额外约束。对比默认参数基线（不剪枝 + 全特征，Train R² 0.9931 / Val R² 0.9509 / MAE 0.0490 / 训练 419s），调优后模型（Train R² 0.9854 / Val R² 0.9489 / MAE 0.0504 / 训练 54s）：训练-验证差距从 0.042 收窄到 0.036，过拟合更小，Val 仅损失约 0.002，换来训练时间从 7 分钟降到 1 分钟，且模型体积与推理速度大幅优化。交叉验证在 5 万调参子样本上以 `cross_validate` 单次 5 折同时取 R² 与 MAE，避免全量双跑 10 折耗时过长。

### 5.5 交叉验证

使用 **5 折交叉验证**（`cv=5`）评估模型在训练集上的稳定性，避免过拟合。

## 6. 两种模型对比方案

### 6.1 对比维度

| 对比维度 | 方案 A（随机森林） | 方案 B（决策树） |
|----------|-------------------|------------------|
| **基线模型** | 默认参数 RandomForestRegressor | 默认参数 DecisionTreeRegressor |
| **调优后模型** | RandomizedSearchCV + GridSearchCV | RandomizedSearchCV + GridSearchCV |
| **评估指标** | R² Score, MAE（训练/验证/测试） | R² Score, MAE（训练/验证/测试） |
| **训练时间** | 记录 wall time | 记录 wall time |
| **过拟合程度** | 训练 vs 验证 R² 差距 | 训练 vs 验证 R² 差距 |

### 6.2 对比输出表格

| 阶段 | 模型 | R² Score（Val） | MAE（Val） | 训练时间 |
|------|------|-----------------|------------|----------|
| 基线（默认参数） | 随机森林 | 0.9509 | 0.0490 | 419s |
| 基线（默认参数） | 决策树 | 0.8973 | 0.0690 | 23s |
| 超参数调优 | 随机森林 | 0.9489 | 0.0504 | 54s |
| 超参数调优 | 决策树 | 0.9229 | 0.0619 | 23s |

> 注：随机森林基线默认参数为 `max_depth=None` 不剪枝 + 全特征，训练集 R² 0.9931、验证集 0.9509，存在明显过拟合（差距 0.042）。调优后验证 R² 仅下降 0.002，但训练-验证差距收窄到 0.036，且训练时间从 7 分钟降到 1 分钟。决策树基线因单棵树容量有限，验证 R² 仅 0.8973；调优后提升到 0.9229，达到单棵树在该数据上的近似上限。

### 6.3 分析方法

1. **定量对比**：调优前后 R² 和 MAE 的变化量（ΔR², ΔMAE），量化超参数优化的收益
2. **泛化分析**：训练集 vs 验证集性能差距，判断模型的过拟合倾向
3. **效率分析**：模型训练时间与性能收益的 trade-off

## 7. 特征重要性分析

### 7.1 方法

- **随机森林**：直接使用 `model.feature_importances_` 获取 Gini Importance（基于分裂节点的不纯度减少量）
- **决策树**：同理提取 feature importance，并可对单棵树做 `plot_tree` 可视化

### 7.2 输出

- 按重要性降序排列的 Top 15 特征列表（含重要值）
- 横向柱状图（`matplotlib`）展示特征重要性排序

### 7.3 预期结论方向

基于 PUBG 游戏机制，预期以下特征对排名影响最大：

| 特征 | 预期推理 |
|------|----------|
| `killPlace` / `kills` | 击杀数直接反映战斗能力，高击杀必然伴随高排名 |
| `damageDealt` | 总伤害是战斗贡献的硬指标 |
| `walkDistance` | 步行距离大 = 搜索资源多、跑圈积极、存活时间长 |
| `boosts` | 能量道具使用多 = 决赛圈存活、需要持续维持血量 |
| `DBNOs` / `assists` | 击倒和助攻反映团队战斗参与度 |
| `weaponsAcquired` | 捡枪多 = 搜索资源更充分 |
| `totalDistance`（新增） | 综合活动范围指标 |
| `killEfficiency`（新增） | 击杀效率反映枪法精准度 |

最终结论将在模型训练完成后，结合实际的 `feature_importances_` 排序和领域知识给出最终分析。

## 8. 执行流程总览

```
1. 数据加载
   ├── 读取 train_V2.csv
   └── 初步探索（shape, info, describe, 缺失值统计）

2. 数据预处理
   ├── 3.1 特殊缺失值清洗（rankPoints, killPoints, winPoints）
   ├── 3.2 剔除无关列（仅 Id；groupId/matchId 保留用于聚合）
   ├── 3.3 matchType One-Hot 编码
   ├── 3.4 异常值 Winsorize 处理（仅连续长尾列）
   ├── 3.5 队伍/比赛聚合特征（team_*, playersInGroup, playersInMatch 等）
   └── 3.6 常规缺失值中位数填充（含未定级缺失指示特征）

3. 特征工程
   ├── 4.1 队伍/比赛聚合特征（关键提升，见 2.5）
   ├── 4.2 totalDistance = walkDistance + rideDistance + swimDistance
   ├── 4.3 killEfficiency = kills / (damageDealt + 1)
   ├── 4.4 teamContribution = assists + revives
   └── 4.5 survivalScore = (heals + boosts) / (kills + DBNOs + 1)

4. 模型训练
   ├── 划分 train/val (80/20)
   ├── 方案A：随机森林基线 + 超参数调优
   └── 方案B：决策树基线 + 超参数调优

5. 模型评估
   ├── 各模型 R² Score / MAE 对比表
   └── 过拟合分析（训练 vs 验证）

6. 特征重要性
   ├── 随机森林 feature_importances_
   ├── Top 15 特征柱状图
   └── 结合游戏机制解读

7. 最终结论
   ├── 哪些特征对 PUBG 获胜最重要
   ├── 两种模型的综合对比与选型建议
   └── 改进方向（如尝试 XGBoost / LightGBM）
```

# MNIST 四网络对比：GPU 重跑结论（RTX 4090 vs CPU 版）

- 日期：2026-09-06
- 环境：AutoDL 容器，RTX 4090（24GB），torch 2.8.0+cu128，cudnn 9.10.02，Python 3.12，Ubuntu 22.04
- 口径与 CPU 版对齐：seed=42（CPU+CUDA 双 RNG）、`s/epoch` 含评估时间、`torch.cuda.synchronize()` 后计时；
  与 CPU 版唯一的运行差异是硬件本身和 `num_workers` 0→4、cudnn 替代 oneDNN
- 实验设计（分组 / 超参 / epoch 数）与 CPU 版逐项一致，`models.py` 逐字节相同

**对比纪律**（详见 `GPU计划.md` §4，这里只放结论）：

- GPU 与 CPU 的数字**不构成同精度对比**，能比的是**结论的方向**；
- GPU 上跨进程的运行间噪声本底实测 **Δacc 0.1~0.4pp**（`smoke.sh` 第 4 项的同配置复跑测得），
  沿用 CPU 版的判定线：**幅度 ≥ 0.2pp 且曲线形态能对上机制解释**才算显著。

## 〇、总账：CPU 版的结论哪些活下来了

| CPU 版结论 | GPU 复现 | 备注 |
|---|---|---|
| 四网络精度极差很小，不能排名 | ✅ | 极差 0.11pp → 0.15pp，仍不可分 |
| 决定耗时的是 FLOPs 不是参数量 | ⚠️ 仅 CPU 成立 | GPU 上被"每 batch 固定开销"地板掩盖（见 §一） |
| GoogLeNet 每 FLOP 成本最高 | ✅ 排序不变 | 每 FLOP 成本排序两硬件完全一致，量级压缩（见 §一） |
| 学习率 100 倍区间不敏感（BN） | ✅ | GPU 极差 0.01pp，比 CPU（0.03pp）还干净 |
| cosine 5 轮 +0.20，全场最佳 | ✅ | +0.26，仍是实验二最佳 |
| cosine 20 轮优势蒸发 | ✅✅ | −0.03 vs CPU −0.04，最佳轮同为 e9，签名逐项复现 |
| augment 是唯一压 gap 的手段 | ✅ | 末轮 gap 0.51pp → 0.13pp；训练损失不塌平 |
| cosine×augment 超线性交互 +0.14 | ⚠️ 方向对 | GPU 交互 +0.06，噪声边缘，置信度降级 |
| **Adam 显著更差（−0.20）** | ❌ **翻转** | GPU +0.04，与基准不可区分（见 §二） |
| bs256 在 CPU 上无吞吐收益 | ✅（GPU 侧证实） | GPU 实测 bs256 快 3.1 倍——"大 batch 收益是 GPU 现象" |
| 训练轮数是最便宜的提升 | ✅ | 5→20 轮 +0.29（CPU +0.24） |

11 条结论：8 条复现、1 条部分复现（交互项）、1 条被证实（bs256 吞吐）、**1 条翻转（Adam）**。

## 一、实验一：四网络（5 epochs）

| 模型 | 参数量 | 最佳 | 末轮 | s/epoch | 总耗时 | vs CPU 加速比 |
|---|---|---|---|---|---|---|
| alexnet | 4.82M | **99.32%** | 99.32% | 6.8s | 0.6 分 | 62× |
| vgg | 1.13M | 99.25% | 99.21% | 8.1s | 0.7 分 | 14× |
| googlenet | 0.27M | **99.40%** | 99.40% | 18.5s | 1.5 分 | 19× |
| resnet | 2.76M | 99.38% | 99.27% | 15.0s | 1.3 分 | 21× |

### 精度：架构对精度的影响依旧可以忽略

四网络极差 0.15pp（99.25–99.40），全部落在验收区间 99.2~99.5%。前二名与 CPU 版相同
（GoogLeNet / ResNet），但 GoogLeNet 与 ResNet 只差 0.02pp，**落在噪声本底内，不能据此排名**——
和 CPU 版"99.37 vs 99.36 不能排名"是同一条结论。MNIST 上架构选择影响的是成本，不是精度。

### 耗时：CPU 版的排序整个翻过来了，且翻转得有规律

| 模型 | MFLOPs | CPU s/epoch（排名） | GPU s/epoch（排名） | CPU s/MFLOP | GPU s/MFLOP |
|---|---|---|---|---|---|
| alexnet | 168.6 | 421s（4） | 6.8s（**1**） | 2.50 | 0.04 |
| vgg | 22.6 | 117s（1） | 8.1s（3） | 5.16 | 0.36 |
| googlenet | 32.1 | 355s（3） | 18.5s（**4**） | 11.05 | 0.58 |
| resnet | 85.2 | 315s（2） | 15.0s（2） | 3.70 | 0.18 |

两个层次的发现：

1. **每 FLOP 成本的排序在两种硬件上完全一致**：GoogLeNet > VGG > ResNet > AlexNet。
   变的只是量级——GoogLeNet 对 VGG 的溢价从 2.1× 压缩到 1.6×，AlexNet 则从 0.48×
   掉到 0.11×。这说明"多分支小算子每 FLOP 更贵、大 GEMM 每 FLOP 更便宜"是**架构的性质**，
   与硬件无关；而"GoogLeNet 慢 3 倍""AlexNet 最慢"这类**具体数字是硬件的性质**。
   CPU 版实验记录里的"待验证：换 GPU 后 Inception 的开销应能被掩盖"——实测答案：
   **被掩盖了一部分，没有全部**。GoogLeNet 在 GPU 上仍是最慢的，参数效率的优势
   体现在精度侧（0.27M 参数拿下四者最高的 99.40%），不在速度侧。
2. **GPU 上出现了新的地板：每 batch 固定开销。** AlexNet 的 FLOPs 是 VGG 的 7.5 倍，
   却比 VGG 快 16%——6.8s 里很大的成分是"每 batch 的 kernel 下发 + H2D 拷贝 + `.item()`
   隐式同步"这份固定开销乘以 938 个 batch。旁证：bs256 组把 batch 扩大 4 倍，
   s/epoch 从 8.1s 降到 2.6s（3.1 倍），说明小 batch 时 GPU 远没喂饱。
   **所以 GPU 版的 s/epoch 在底部端（alexnet/vgg）测的是管线和启动开销，只有顶部端
   （googlenet/resnet）才是模型本身的差异**——这正是 CLAUDE.md 预告的混淆项，部分应验。

## 二、实验二：VGG 超参数单变量（5 epochs）

| 配置 | GPU 最佳 | GPU Δ | CPU Δ | 方向 |
|---|---|---|---|---|
| baseline | 99.25% | — | — | — |
| lr=0.001 | 99.25% | +0.00 | +0.03 | 一致：无差异 |
| lr=0.1 | 99.24% | −0.01 | +0.03 | 一致：无差异 |
| adam lr=0.001 | 99.29% | +0.04 | **−0.20** | ❌ **翻转** |
| batch=256 | **99.38%** | +0.13 | −0.07 | 均在噪声内；吞吐见下 |
| cosine | **99.51%** | **+0.26** | +0.20 | 一致：正收益 |
| augment | 99.46% | **+0.21** | +0.18 | 一致：正收益 |

- **学习率不敏感完美复现**：0.001~0.1 的 100 倍区间内 GPU 极差只有 0.01pp。
  有 BN 的网络上不值得做 lr 网格搜索——这条在 GPU 上比 CPU 上还干净。
- **cosine / augment 复现且更强**：+0.26 / +0.21，双双过 0.2pp 判定线（CPU 版 +0.20 / +0.18
  本来就贴着判定线）。cosine 5 轮曲线末轮即最佳（99.51%），e3 起一路上行，"预算紧就开 cosine"
  的实践结论在 GPU 上以 10 倍便宜的价格成立（5 轮 VGG 只要 0.7 分钟）。
- **Adam 翻转，是三组实验里唯一方向相反的结论。** CPU 版"唯一显著变差的一组（−0.20，
  且 e3→e4 大回退 99.07→98.74）"在 GPU 上变成 +0.04 的无差异，大回退签名也没有复现
  （GPU 的 adam 只有 e2 一个 −0.26 的小坑随即收回）。两种可能：CPU 的 −0.20 贴着判定线，
  本来就可能是特定数据顺序下的轨迹运气；或 Adam 的劣势对数值环境敏感。
  **教训：负向结论（"X 更差"）同样需要跨硬件复验，单硬件单 seed 的 −0.20 不足以定案。**
  （公平性注记不变：这比的是未调参的 Adam vs 已调参的 SGD。）
- **bs256 证实了 CPU 版的预测**：CPU 版写"大 batch 的吞吐收益是 GPU 现象"，GPU 实测
  正是如此——s/epoch 8.1s→2.6s（3.1×），而精度 +0.13 在噪声内、测试曲线前 4 轮单调上升，
  无泛化变差信号。想快，开 bs256，不丢精度。

## 三、实验三：VGG 20 轮 2×2 因子（cosine × augment）

| 配置 | GPU 最佳 | GPU Δ | CPU Δ | 末轮 |
|---|---|---|---|---|
| e20_base | 99.54% | — | — | 99.49% |
| e20_cos | 99.51% | −0.03 | −0.04 | 99.46% |
| e20_aug | **99.60%** | +0.06 | +0.04 | 99.43% |
| e20_cosaug | **99.63%** | **+0.09** | **+0.14** | 99.60% |

- **训练轮数依然是最便宜的提升**：5→20 轮 +0.29（99.25→99.54），高于其余一切单项。
- **cosine 的"5 轮结论在 20 轮被推翻"逐字复现**：Δ 从 +0.26 变 −0.03（CPU：+0.20→−0.04），
  最佳轮停在 **e9，之后 11 轮再没超过**——与 CPU 版的最佳轮完全相同。机制也对上了：
  e9 起 train_acc 100%、训练损失降到 3e-4，损失面塌平后调度器无事可做。
  cosine 的价值是加速收敛，不是提高上限。
- **augment 的机制复现**：训练损失 20 轮末仍有 0.0141（e19 最低 0.0134；CPU 0.0134，同量级）、
  train_acc 99.56% 停在 100% 之下——模型背不下增强后的训练集，损失面不塌。
  它是唯一把末轮 train-test gap 压下去的配置（0.51pp → 0.13pp；CPU 0.49 → 0.08）。
- **交互项方向复现、幅度减半**：+0.09 = (−0.03) + (+0.06) + 交互 **+0.06**（CPU +0.14）。
  组合仍是四组最高（99.63%），末轮 99.60 几乎不掉（−0.03），曲线从 e7 起大体压制其余三组
  ——但 +0.06 只相当于 6 张图，在本底内。**CPU 版"必须两个一起开，单开等于白跑"的强结论
  在 GPU 上应降级为"组合仍最优，但交互幅度小，需要多 seed 坐实"**；单开 augment（+0.06）
  并不吃亏。
- **过拟合四信号检查**（可靠性排序：测试曲线回落 > 最佳轮远早于末轮 > train loss→0 > gap 变大）：

  | 组 | 测试曲线 | 最佳轮 | train loss 末值 | 判定 |
  |---|---|---|---|---|
  | base | 平台波动 99.3~99.5，无回落 | e19（≈末轮） | 0.0001（e13 起 train 100%） | 记住了训练集但测试不塌，非过拟合主导 |
  | cos | e9 见顶后平台 | e9 | 0.0003 | 同上；"停滞"是损失面塌平，不是过拟合 |
  | aug | 大幅波动，e18 见顶 | e18（≈末轮） | 0.0141（不塌） | 无过拟合；末轮 −0.17 是单点波动 |
  | cosaug | e7 后整体最高，平稳 | e11 | 0.0099（不塌） | 无过拟合 |

  与 CPU 版结论一致：11 组实验没有一组出现明确的测试曲线回落，**过拟合不是这个任务的主要矛盾**。

## 四、GPU 实践排名

| 配置 | 轮数 | 最佳 | 总耗时 |
|---|---|---|---|
| **VGG + cosine + augment** | 20 | **99.63%** | 2.7 分 |
| VGG + augment | 20 | 99.60% | 2.6 分 |
| VGG 基准 | 20 | 99.54% | 2.7 分 |
| VGG + cosine | 5 | 99.51% | 0.7 分 |
| ResNet 基准 | 5 | 99.38% | 1.3 分 |
| VGG bs256 | 5 | 99.38% | 0.2 分 |
| VGG 基准 | 5 | 99.25% | 0.7 分 |

- **预算紧**：`--scheduler cosine` 5 轮，0.7 分钟拿 99.51%
- **要最好**：cosine + augment 20 轮，2.7 分钟拿 99.63%（CPU 版同样的配方要 45 分钟）
- **要最快**：bs256，0.2 分钟拿 99.38%，精度不亏
- "调超参比换架构划算"的总结论成立：调过超参的 VGG（99.63%）比四网络里架构最优的
  GoogLeNet（99.40%）还高 0.23pp——**超参带来的收益（+0.29~+0.38pp）大于任何两个架构之间的
  差距（≤0.15pp）**。CPU 版"VGG 参数只有 ResNet 的 41%"的附加说明在 GPU 上不成立
  （GPU 侧架构最优是参数最少的 GoogLeNet，VGG 参数是它的 4.2 倍），但这不影响主结论：
  架构间差距太小，谁当基准都一样。

## 六、方法论收获（这次重跑教了什么）

1. **稳固的结论是"方向"，不是数字。** 跨硬件复现的 8 条全部是方向级结论；
   翻转的 Adam 恰好是 CPU 版里贴着判定线（−0.20 vs 判定线 0.2）的那条。
   单硬件单 seed 下刚过判定线的结论，无论正负，都应视为待复验。
2. **"架构的性质"和"硬件的性质"要分层记录。** 每 FLOP 成本排序
   （GoogLeNet > VGG > ResNet > AlexNet）跨硬件不变，是架构的性质；
   排名、倍数、快慢的具体数字全部随硬件重排。换个硬件重跑一遍，
   是区分这两类结论的唯一便宜手段。
3. **GPU 上测耗时先找地板。** MNIST 这种小模型小数据，s/epoch 的底部被
   "每 batch 固定开销 × batch 数"托住（bs256 一项就 3.1× 加速），底部端模型的
   耗时差异测的不是架构。结论里要写明测到的是什么。
4. **噪声本底要实测，不能引用。** ±0.1pp 的引用值与本机实测（0.1~0.4pp，波动）
   差了 4 倍；`smoke.sh` 的同配置复跑 30 秒就能量出来，这个口径修改已固化进脚本。

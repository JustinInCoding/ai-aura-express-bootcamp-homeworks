# 实验方案与命令记录

本文件记录所有已跑和待跑的实验配置、对应命令、以及每组想验证的假设。
跑完后回来对照"预期"与"实际"，差异本身就是作业要分析的内容。

结果统一落在 `results/`：每组一个 `{tag}_{model}.json`，另有 `summary.csv` 汇总所有
实验的一行摘要；图在 `results/figs/`。

## 1. 实验一：四网络架构对比（已完成）

**目的**：同一数据集、同一超参数下横向比较四种经典架构。

固定超参数（下面超参数实验的基准）：

| 项 | 值 |
|---|---|
| epochs | 5 |
| batch_size | 64 |
| lr | 0.01 |
| optimizer | SGD, momentum=0.9 |
| weight_decay | 0 |
| scheduler | 无 |
| 数据增强 | 无 |
| seed | 42 |
| 输入尺寸 | 28×28 原生 |

```bash
# 四个网络依次训练，崩溃自动续训重试，跑完自动汇总出图
THREADS_GOOGLENET=2 bash run_all.sh 5 baseline
```

单独重跑某一个：

```bash
python -u train.py --model resnet --epochs 5 --tag baseline
```

### 结果

| 模型 | 参数量 | 最佳测试准确率 | 末轮准确率 | best−final | 单 epoch 耗时 | 总耗时 |
|---|---|---|---|---|---|---|
| alexnet | 4.82M | 99.26% | 99.22% | +0.04 | 421s | 35.1 分 |
| vgg | 1.13M | 99.29% | 99.19% | +0.10 | 117s | 9.7 分 |
| googlenet | 0.27M | 99.36% | 99.36% | +0.00 | 355s | 29.6 分 |
| resnet | 2.76M | **99.37%** | 99.24% | +0.13 | 315s | 26.3 分 |

四者准确率只差 0.11 个百分点，但参数量差 18 倍、耗时差 3.6 倍。

补充计算量数据（前向 hook 统计 `Conv2d`/`Linear` 的乘加次数，单样本 28×28）：

| 模型 | 参数量 | MFLOPs | Conv2d 层数 | 串行深度 | s/epoch | s/MFLOP |
|---|---|---|---|---|---|---|
| alexnet | 4.82M | 168.6 | 5 | 5 | 421.3 | 2.50 |
| vgg | 1.13M | 22.6 | 6 | 6 | 116.6 | 5.16 |
| googlenet | 0.27M | 32.1 | 19 | 7 | 354.8 | 11.05 |
| resnet | 2.76M | 85.2 | 16 | 13 | 315.4 | 3.70 |

> 「串行深度」= 从输入到输出的最长卷积路径。GoogLeNet 的 19 个卷积分布在 4 条并行支上，
> 最长路径只有 7 层；ResNet 的 16 个里有 3 个是 1×1 投影捷径，主干串行 13 层。

**观察**

1. **VGG 是本次的性价比冠军。** 相比 AlexNet，参数降到 1/4、耗时降到 1/3.6，准确率还略高。
   真正决定耗时的是 FLOPs 而非参数量：VGG 22.6 vs AlexNet 168.6 MFLOPs，差 7.5 倍。
   VGG 省在把大通道层推到了 3×3 的小特征图上（卷积参数与特征图尺寸无关，但计算量要乘 H×W）。

2. **GoogLeNet 参数最少却排第二慢，是 CPU 环境的结构性劣势。** 它的 `s/MFLOP` 高达 11.05，
   是 VGG 的 2 倍多 —— 说明瓶颈不在计算量（32.1 MFLOPs 只有 ResNet 的 1/2.7），
   而在 19 个算子 + 每个 Inception 四分支再 `cat` 带来的启动与访存开销。
   Inception 的「并行」是结构上的多分支，在 CPU 上仍然逐个串行执行，拿不到并行收益。
   **待验证**：换 GPU 后这部分开销应能被掩盖，届时它的参数效率优势才体现得出来。

3. **ResNet 主干最深（13 层串行），且是唯一在 5 epochs 内没有明显掉头的深网络**，
   但它 99.37% 与 GoogLeNet 99.36% 只差 0.01 个百分点 —— 单 seed、单次运行，
   **这个排名落在噪声范围内，不能据此说 ResNet 更准**（同实验二的判断标准）。
   能说的是：残差捷径让 13 层深度在小数据集上没有出现退化。

4. **GoogLeNet 可能还没收敛。** 逐轮曲线 `97.41 → 99.16 → 99.00 → 98.94 → 99.36`
   在第 5 轮才冲到最高，是四者中唯一 `best == final` 的。另外三个都在第 3–4 轮见顶后回落。
   5 epochs 对它偏短，拉长轮数它有可能继续涨。

## 2. 实验二：超参数单变量对照（已完成）

**目的**：调整超参数并观察准确率变化。

**为什么固定用 VGG**：它 117s/epoch，是四个网络里最快的，6 组约 1 小时；
同样的实验换 AlexNet 要 4 小时以上。超参数的作用规律在各架构间是通用的。

**为什么每组只改一个变量**：同时改多个的话，准确率的变化无法归因到具体哪一项。
基准直接复用 `results/baseline_vgg.json`，不必重跑。

### 一次跑完

```bash
bash sweep.sh 5
```

`sweep.sh` 会依次跑下面 6 组，已有结果的自动跳过，崩溃自动续训重试（最多 3 次），
最后调用 `sweep_compare.py` 出对比表和图。

### 6 组配置

| 标签 | 改动 | 想验证什么 | 预期 |
|---|---|---|---|
| `lr001` | lr 0.01 → 0.001 | 学习率过小 | 5 epochs 内收敛不完全，欠拟合，准确率下降 |
| `lr1` | lr 0.01 → 0.1 | 学习率过大 | 损失曲线震荡，可能不如基准甚至发散 |
| `adam` | SGD → Adam(lr=1e-3) | 自适应优化器 | 前几个 epoch 收敛更快，最终与 SGD 接近 |
| `bs256` | batch 64 → 256 | 大 batch | 更新次数少 1/4，同 lr 下欠训练；但单 epoch 更快 |
| `cosine` | 加余弦退火 | 学习率调度 | 后期小 lr 精修，末轮准确率更稳，略优于基准 |
| `augment` | 加随机旋转+平移 | 数据增强的正则化 | train/test gap 缩小；5 epochs 太短，可能反而略降 |

### 逐组单独跑

想单独跑某一组（例如只补 `adam`）：

```bash
python -u train.py --model vgg --epochs 5 --lr 0.001                   --tag lr001
python -u train.py --model vgg --epochs 5 --lr 0.1                     --tag lr1
python -u train.py --model vgg --epochs 5 --optimizer adam --lr 0.001  --tag adam
python -u train.py --model vgg --epochs 5 --batch-size 256             --tag bs256
python -u train.py --model vgg --epochs 5 --scheduler cosine           --tag cosine
python -u train.py --model vgg --epochs 5 --augment                    --tag augment
```

### 单独汇总

```bash
python -u sweep_compare.py --model vgg
```

输出：
- `results/sweep_vgg_table.md` —— markdown 表格，可直接贴进 README
- `results/figs/sweep_vgg_curves.png` —— 各配置的准确率/损失曲线（基准为粗黑线）
- `results/figs/sweep_vgg_delta.png` —— 相对基准的准确率变化柱状图

### 结论

#### 先说一个前提：多数差异在噪声范围内

7 组的准确率全部落在 99.09%–99.49%，极差只有 **0.40 个百分点**。测试集 10000 张，
0.20pp 就是 **20 张图**。只跑了一个 seed，因此 `lr001`/`lr1` 的 +0.03（3 张图）
根本不能算"更好"。

下面只把满足两个条件的结论当作真实的：**幅度 ≥ 0.2pp**，且**有机制上的解释、
曲线形态能对上**。其余一律记作"无显著差异"。

（顺带一个自检：`cosine` 的 e1 与 `baseline` 完全一致，都是 98.76 / 0.1037 ——
因为余弦退火第一个 epoch 的 lr 就是 0.01，且 seed 相同。这说明实验的随机性
控制住了，各组之间的差异不是来自数据顺序不同。）

#### 1. 学习率调度是本次唯一"免费"的提升 ✅

`cosine` 拿到最高的 99.49%（+0.20），而**耗时与基准完全相同**（都是 116.6s/epoch）——
余弦退火只是每个 epoch 改一次学习率的标量，没有任何额外计算。

机制很清楚：看训练损失，`cosine` 的 e5 降到 **0.0044**，是全部 7 组里最低的，
不到基准（0.0095）的一半。后期学习率变小 → 参数更新步长变小 → 能停进更窄的极小值，
而不是在里面来回蹦。

更关键的是曲线形态：`cosine` 的测试准确率**单调上升**（98.76 → 98.99 → 99.40 →
99.41 → 99.49），末轮就是最佳轮。而基准在 e3 就见顶（99.29），之后掉到 99.22、99.19。

> **实践结论：调度器应该默认打开。**它零成本、无副作用，且让"最后一轮"和
> "最好一轮"重合 —— 省掉了挑选最佳 checkpoint 的麻烦。

#### 2. 数据增强的效果和预期相反 ❌ 预期错了

我事先判断"5 epochs 太短，增强来不及体现收益，可能反而略降"。**实际 +0.18，
排第二。**

判断错在哪：我以为增强的收益需要长时间训练才能累积，但忽略了它的作用是**即时**的 ——
每个 batch 看到的都是新的扰动样本，等价于训练集被瞬间放大，从第一个 epoch 就在起作用
（`augment` 的 e1 是 99.04%，是全部 7 组里最高的 e1）。

最有说服力的是 gap 那一列：`augment` 是**唯一一个负 gap 的配置**（−0.42），
train 99.05% 反而**低于** test 99.47%。这正是数据增强的特征信号 ——
模型训练时面对的是被旋转平移过的"更难"的样本，测试时面对的是干净样本，
所以测试反而更容易。

代价是训练损失明显偏高（e5 为 0.0308，是 `cosine` 的 7 倍），以及 **+8% 的耗时**
（126s vs 117s，来自 CPU 上做仿射变换）。但这个"损失高"不是坏事，它意味着模型
远没有把训练集背下来 —— 也就是说，**这一组还有很大的继续训练空间**。

#### 3. 学习率在 0.001–0.1 这 100 倍区间内几乎不影响最终结果 ❌ 两个预期都错了

预期 `lr001` 欠拟合、`lr1` 震荡。实际两者都是 **+0.03，即无差异**。

- `lr001`（小 100 倍）：起步确实慢很多，e1 训练损失 0.3041 vs 基准 0.1037，
  差 3 倍 —— **这部分预期是对的**。但 5 个 epoch 足够它追上来，且因为步长小、
  相当于隐式正则，它的曲线是单调上升的，末轮 99.32% 反而**高于**基准的末轮 99.19%。
- `lr1`（大 10 倍）：预期的发散没有出现。e3 见顶 99.32 后回落到 99.14、99.20，
  只能看出轻微的不稳定。

为什么大学习率没炸？**因为模型里每个卷积后面都有 BatchNorm。**BN 把每层输入
重新归一化，直接压掉了梯度的尺度差异，使损失面对学习率的容忍度大幅提高。
这也是 BN 论文里明确宣称的收益之一 —— "可以用更大的学习率"。

> 这一条改变了我对调参优先级的认识：**在有 BN 的网络上，学习率不再是那个
> 一调就崩的敏感参数**，不值得花大量时间在它上面做网格搜索。

#### 4. 大 batch 没有换来速度，训练集拟合更紧但泛化未见变差 ⚠️ 部分预期错了

`bs256` 是 −0.07（无显著差异），但两个细节值得看：

- **速度几乎没提升**：112s vs 117s，只快 4%。我预期"大 batch 更吃并行所以更快"，
  在**只有 4 个物理核**的 CPU 上不成立 —— batch=64 已经足够把 4 个核喂饱，
  再增大只是让每次矩阵乘更大，总浮点运算量不变，自然不会更快。
  （大 batch 的吞吐收益是 GPU 上的现象：GPU 有几千个核，小 batch 根本喂不满。）
- **训练集拟合得最紧**：train_acc 99.87%、训练损失 0.0071，都接近全场最紧，
  gap +0.65 也是全场最高。这有点反直觉 —— 它的**参数更新次数只有基准的 1/4**
  （5×235=1175 次 vs 5×938=4690 次），却把训练集记得更牢。

**但"拟合更紧"不等于"过拟合了"。**按 5.9 的四条信号逐个检查：

| 信号 | `bs256` 的表现 | 是否支持过拟合 |
|---|---|---|
| 1. 测试见顶后持续下滑 | 98.31→98.89→99.18→99.13→**99.22**，末轮即最佳 | ❌ 没有 |
| 2. 最佳轮远早于末轮 | 最佳轮 = e5 = 末轮 | ❌ 没有 |
| 3. 训练损失趋近 0 | 0.0071，低但未塌 | ⚠️ 弱 |
| 4. train/test gap | +0.65，全场最高 | ✅ 唯一支持项 |

四条里只有最弱的那条成立，另外两条明确反向。**更关键的是**：`bs256` 的末轮
测试准确率 **99.22%** 比 `baseline` 的末轮 **99.19%** 还高。那个 −0.07 是拿
"最佳轮"比出来的 —— 而 baseline 的最佳轮 99.29% 出现在 e3，之后一路掉到 99.19%。
**论过拟合的行为特征，反倒是 baseline 更明显**（唯一见顶回落的），`bs256` 全程单调上升。

**还有一个混淆变量**：`bs256` 只更新了 1175 次，在"同样跑 5 个 epoch"这个口径下
**其实是训练得更少的那个**。两组不在同一优化进度上，拿 gap 直接比本身就不严谨。
公平的对比应该按"相同更新次数"对齐，即让 `bs256` 跑 20 个 epoch。

> **文献机制（本次数据不足以验证）**：大 batch 的梯度是更多样本的平均，噪声更小；
> 而 SGD 的梯度噪声本身是一种隐式正则化，噪声小了模型更容易走向尖锐的极小值、
> 泛化更差（Keskar et al. 2017 的经典结论）。这个机制是真实的，但本次
> 0.07pp 的差距落在噪声内，**既没证明也没证伪它**。

> 结论：**在 CPU 上调大 batch 没有收益**，速度只快 4%，准确率无显著变化，
> 唯一确定的观测是训练集被拟合得更紧。如果确实要用大 batch，
> 需要同步放大学习率（线性缩放规则）来补偿更新次数的减少。

#### 5. Adam 不是"换上就更好"的直接替代品 ✅

`adam` 是唯一显著变差的一组：**99.09%（−0.20）**，且曲线最不稳定 ——
e3 到 e4 从 99.07% 掉到 98.74%，是全场最大的单轮回退。

我的预期是"前几轮收敛更快、最终与 SGD 接近"。前半句对了（e1 的 98.83% 高于基准
的 98.76%），后半句不对，它最终**没能追上**调好的 SGD+momentum。

这与学界的普遍观察一致：Adam 收敛快、对学习率不敏感，**适合快速拿到一个可用的
baseline**；但在超参数已经调好的任务上，SGD+momentum 的最终泛化通常更好。
这里用的 1e-3 是 Adam 的通用默认值，并没有针对本任务调过 —— 公平地说，
这一组比的是"未调参的 Adam"和"已调参的 SGD"。

#### 汇总：哪些超参数值得花时间

按本次实验的影响力排序：

| 超参数 | 影响 | 成本 | 建议 |
|---|---|---|---|
| 学习率调度 | **+0.20** | 零 | **必开**，免费收益 |
| 数据增强 | **+0.18** | +8% 耗时 | 推荐，且轮数越多收益越大 |
| 优化器选择 | −0.20 | 零 | SGD+momentum 已够好，换 Adam 需重调 lr |
| batch size | −0.07 | −4% 耗时 | CPU 上无收益，保持 64 |
| 学习率数值 | +0.03 | 零 | 有 BN 时不敏感，0.001–0.1 都能用 |

> **⚠️ 上表的前两行在 20 epochs 下不成立**，见实验三：轮数拉长后
> 学习率调度变成 −0.04、数据增强变成 +0.04，两者单独用的优势都会消失。
> "学习率调度 = 免费提升"这个结论只在训练预算紧张时正确。

**最佳配置：`cosine`，99.49%** —— 比四网络对比中最好的 ResNet（99.37%）还高
0.12pp，而 VGG 的参数量只有 ResNet 的 41%、单 epoch 快 2.7 倍。
**说明在这个任务上，调好超参数比换更复杂的架构更划算。**

#### 两个待验证的方向

1. **5 个 epoch 不够**：`cosine` 和 `augment` 的末轮都是最佳轮，说明两者都还在
   上升期。特别是 `augment` 的训练损失还高达 0.0308，远未收敛。
   延长到 15–20 epochs 很可能拉开更大差距。
2. **`cosine` + `augment` 组合**：两者机制不冲突（一个管优化路径、一个管数据分布），
   且过拟合方向互补（cosine gap +0.42、augment gap −0.42），理论上可叠加。
   本次是严格的单变量对照，没有测组合。

→ 见下面的实验三。**第 1 点验证结果是错的，第 2 点是对的。**

## 3. 实验三：20 epochs 下的 cosine × augment 因子实验（已完成）

**目的**：验证实验二末尾的两个方向。

**为什么不能只跑一条 `--epochs 20 --scheduler cosine --augment`**：那样同时改了
轮数、调度、增强三样，涨了多少都无法归因。所以做成 2×2 因子设计，其中
`e20_base` 是 20 epochs 下自己的基准 —— 没有它，就分不清 `e20_cos` 的变化
是 cosine 的功劳还是多跑 15 轮的功劳。

四组齐了还有一个额外好处：能算**交互项**，直接回答"能否叠加"。

```bash
bash long.sh 20
```

### 结果

| 配置 | scheduler | augment | 最佳准确率 | 相对 `e20_base` | 最佳轮 | 末轮准确率 | 单 epoch 耗时 |
|---|---|---|---|---|---|---|---|
| `e20_base` | none | off | **99.53%** | — | e15 | 99.51% | 114s |
| `e20_cos` | cosine | off | **99.49%** | −0.04 | e9 | 99.46% | 118s |
| `e20_aug` | none | on | **99.57%** | +0.04 | e13 | 99.47% | 132s |
| `e20_cosaug` | cosine | on | **99.67%** | **+0.14** | e16 | **99.65%** | 132s |

过拟合观察（末轮 train_acc − test_acc）：

| 配置 | train_acc | test_acc | gap | 末轮训练损失 |
|---|---|---|---|---|
| `e20_base` | **100.00%** | 99.51% | +0.49 | 0.0002 |
| `e20_cos` | **100.00%** | 99.46% | +0.54 | 0.0003 |
| `e20_aug` | 99.56% | 99.47% | +0.08 | 0.0134 |
| `e20_cosaug` | 99.68% | 99.65% | **+0.03** | 0.0098 |

### 结论

#### 1. "5 epochs 不够"这个判断错了 —— 轮数拉长后，两个单项的优势全部消失 ❌

对比 5 轮和 20 轮的同名配置：

| 配置 | 5 epochs | 20 epochs | 变化 |
|---|---|---|---|
| 基准（无调度无增强） | 99.29% | 99.53% | **+0.24** |
| cosine | 99.49% | 99.49% | **0.00** |
| augment | 99.47% | 99.57% | +0.10 |
| 相对基准的优势（cosine） | **+0.20** | **−0.04** | 优势蒸发 |
| 相对基准的优势（augment） | **+0.18** | **+0.04** | 优势蒸发 |

我预期"延长到 20 epochs 会拉开更大差距"，**实际是差距被抹平了**。

错在哪：我把"末轮即最佳轮"读成了"这个配置还有上升空间"，但真正在上升期的
**是基准自己**。基准从 99.29% 涨到 99.53%（+0.24），涨幅超过 cosine 和 augment
在 5 轮时的全部优势。也就是说，5 轮实验里 cosine/augment 那 +0.2pp
**并不是"更高的天花板"，而只是"更快到达同一个天花板"** —— 基准只是没训够。

`cosine` 这一组最能说明问题：它的最佳轮出现在 **e9（99.49%）**，之后 11 轮里
学习率一路降到 6e-5，测试准确率却再也没有超过 e9。原因在训练损失那一列：
e11 时 train_acc 已经 **100.00%**、损失 0.0005。**训练集被完全记住之后，
调度器就无事可做了** —— 学习率再怎么精细地退火，也只是在一个已经归零的损失面上
挪动，不可能带来新的泛化收益。

> 修正后的结论：**学习率调度的价值是"加速收敛"，不是"提高上限"。**
> 它在训练预算紧张时收益明显（5 轮 +0.20），预算充足时收益归零（20 轮 −0.04）。
> 5 轮实验里我写的"调度器应该默认打开、免费收益"仍然成立，但理由要改 ——
> 不是因为它更强，而是因为它让你**用更少的轮数拿到同样的结果**。

#### 2. `cosine` + `augment` 确实能叠加，而且是超线性叠加 ✅

交互项 = `cosaug` − `cos` − `aug` + `base` = 99.67 − 99.49 − 99.57 + 99.53 = **+0.14**

这个数是正的，意味着组合的效果**超过**两个单项效果之和：

- 单独 cosine：−0.04
- 单独 augment：+0.04
- 两者相加的预期：**0.00**（即"跟基准没区别"）
- 实际组合：**+0.14**

换句话说，`e20_cosaug` 的 +0.14 **完全来自交互，而不是来自任何一项本身**。
两个单独都没用的改动，凑在一起有用了。

机制上讲得通，关键在上一条发现的那个"调度器无事可做"：

1. `augment` 每个 batch 都在生成新的扰动样本，训练集事实上被无限放大，
   所以模型**永远记不住** —— `e20_aug` 跑满 20 轮，train_acc 只有 99.56%，
   训练损失 0.0134，是 `e20_base`（0.0002）的 **82 倍**。
2. 损失面没有塌成零，**调度器才重新有了发挥空间** —— 后期小学习率是在一个
   仍然崎岖的损失面上做精修，而不是在平地上空转。
3. 反过来看也成立：`augment` 单独用时曲线一直在抖（e13 99.57 → e14 99.48 →
   e15 99.56 → e20 99.47，末轮比最佳轮低 0.10），因为增强带来的梯度噪声
   到最后也没衰减。**cosine 正好负责把这个噪声按下去** ——
   `e20_cosaug` 从 e11 起就稳定在 99.6% 以上，末轮 99.65% 与最佳轮 99.67% 只差 0.02。

> **这是本次全部实验里最有价值的一条：两个超参数的效果不能各自测完再相加。**
> 如果只做单变量对照（实验二的做法），20 轮下会得到"cosine 没用、augment 没用"
> 的结论，从而永远不会去试这个组合 —— 而它恰恰是全场最好的配置。
> 单变量对照能保证归因清晰，但**代价是看不见交互**。

#### 3. gap 那一列给出了独立的佐证

| 配置 | gap | 说明 |
|---|---|---|
| `e20_base` | +0.49 | train 100%，完全记住训练集 |
| `e20_cos` | +0.54 | 同样 100%，调度器没能阻止记忆 |
| `e20_aug` | +0.08 | 增强有效抑制了记忆 |
| `e20_cosaug` | **+0.03** | 几乎不过拟合，且准确率最高 |

注意 `e20_cos` 的 gap（+0.54）比基准（+0.49）还**略大**一点。这再次说明
**学习率调度不是正则化手段** —— 它只影响优化路径怎么走，不影响模型能记住多少。
真正压过拟合的是 augment（改变数据分布），gap 从 +0.49 直接砍到 +0.08。

5 轮实验里我看到 `cosine` gap +0.42、`augment` gap −0.42，据此判断"过拟合方向
互补，理论上可叠加"。**结论蒙对了，但推理过程是错的** —— cosine 的 +0.42
不是"它偏向过拟合"，只是它收敛更快所以 train_acc 更早冲高；20 轮下基准
也一样冲到 100%，两者 gap 就趋同了（+0.49 vs +0.54）。真正让叠加成立的
不是 gap 互补，而是上面第 2 条讲的"augment 保住了损失面的坡度"。

#### 4. 一个必须说明的前提：这些差异仍然很小

四组落在 99.49%–99.67%，极差 **0.18pp = 18 张图**。单 seed，没有误差棒。

交互项 +0.14（14 张图）之所以值得当真，不是因为幅度，而是因为**曲线形态支持它**：
`e20_cosaug` 从 e9 起就持续高于其余三组（e9 99.60 / e11 99.64 / e13 99.64 /
e16 99.67），是 12 个连续 epoch 的稳定领先，不是某一轮的运气。相比之下
`e20_aug` 的 +0.04 就只能算噪声。

要把 +0.14 坐实，需要跑 3–5 个 seed 看均值±标准差。按 44 分钟/组算，
4 组 × 3 seed ≈ 8.8 小时，本机 CPU 上暂时没做。

#### 汇总：三次实验的最终排名

| 配置 | 轮数 | 最佳准确率 | 备注 |
|---|---|---|---|
| **`e20_cosaug`** | 20 | **99.67%** | **全场最佳**，且末轮≈最佳轮，无需挑 checkpoint |
| `e20_aug` | 20 | 99.57% | |
| `e20_base` | 20 | 99.53% | 光靠多跑 15 轮就 +0.24 |
| `cosine`（5 轮） | 5 | 99.49% | **性价比最高**：9.7 分钟拿到 99.49% |
| `resnet`（5 轮基准） | 5 | 99.37% | 参数量是 VGG 的 2.4 倍 |
| `baseline`（5 轮） | 5 | 99.29% | |

两条实践结论：

- **预算紧**（10 分钟以内）：用 `cosine`，5 轮 99.49%。调度器把收敛压缩到最少轮数。
- **要最好**（45 分钟）：用 `cosine + augment`，20 轮 99.67%。
  必须两个一起开，单开任何一个都等于白跑。

最终 99.67% 比四网络对比中最好的 ResNet（99.37%）高 **0.30pp**，
而 VGG 的参数量只有 ResNet 的 41%。**调超参数比换架构划算**这个结论，
在 20 轮下比 5 轮时更成立。

#### 下一步可做的

1. **多 seed 验证**：3–5 个 seed 重跑这 4 组，给交互项 +0.14 加上误差棒。
   这是目前最大的短板。
2. **`augment` 还没收敛**：`e20_aug` 的训练损失 20 轮末仍有 0.0134，
   train_acc 99.56% < 100%。这组是四组里唯一还有明确上升空间的，
   跑 40–50 轮可能继续涨。
3. **把 cosaug 搬到 ResNet/GoogLeNet 上**：本次交互只在 VGG 上测过，
   值得确认它是不是架构无关的通用规律。

## 5. 超参数详解：含义与取值考量

> 以下为实验二、三中涉及的全部超参数，按"刚入门需要理解的程度"来解释。
> 要理解为什么取某个值，先得知道这个参数是干什么的。

---

### 5.1 学习率（learning rate, lr）

**是什么**：每次参数更新迈多大的步子。

把训练想象成蒙着眼在一个山坡上往下走找最低点。学习率就是你迈一步的幅度。

- 步子太小 → 走得很慢，给定时间内到不了底（欠拟合）
- 步子太大 → 可能直接从山谷跨到对面山上去（震荡/发散）

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **0.01**（基准） | 深度学习里对 MNIST 这种简单任务的常用起点。太大太小一眼就能看出来。 |
| **0.001**（缩小 100 倍） | 想验证"步子太小到底会不会欠拟合"。100 倍是足够大的跨度，如果缩 100 倍都没影响，那说明学习率确实不敏感。 |
| **0.1**（放大 10 倍） | 想验证"步子太大到底会不会发散"。10 倍也是常规认知里"该出问题"的幅度。 |

**本实验的结果**：因为有 BatchNorm，0.001–0.1 之间几乎没区别。学习率在"有 BN 的网络"上的敏感度比想象中低很多。

---

### 5.2 优化器（optimizer）

**是什么**：决定"迈步"的具体策略。SGD 和 Adam 是两种主流选择。

**SGD（随机梯度下降）**：
- 最简单的策略：朝着当前最陡的方向迈一步，步长 = 学习率
- `momentum=0.9` 加了「惯性」—— 当前迈步方向 = 本次梯度 × 0.1 + 上次方向 × 0.9，避免来回震荡
- 就像下坡时借着惯性冲，不会每走一步都急转弯

**Adam**：
- 给每个参数单独配一个自适应步长，频繁更新的参数自动变小步长，不常更新的自动变大
- 它的默认学习率是 0.001，不是 0.01，所以换 Adam 时同步改了 lr
- 优势：对学习率不敏感，新手友好，通常很快能拿到可用的结果
- 劣势：最终收敛的泛化能力通常不如调好的 SGD+momentum

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **SGD, lr=0.01, momentum=0.9**（基准） | 经典配置，大部分 CNN 论文的默认优化器。动量 0.9 是业界共识，几乎没人调这个。 |
| **Adam, lr=0.001** | 想验证"换上 Adam 是不是无脑更好"。lr=0.001 是 Adam 论文推荐的默认值。 |

**说明**

PyTorch 里优化器必须自己显式创建，不写就没有，代码根本跑不起来：

  opt = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9)  # 必须写

  这里的"默认 sgd"只是 train.py 自己的 argparse 默认值，是我们定的，不是 PyTorch 定的。

  但"社区习惯上先选哪个"确实有倾向，而且和任务类型有关：

  ┌─────────────────────────────────┬────────────────────┬──────────────────────────────────────┐
  │              场景               │      惯用选择      │                 原因                 │
  ├─────────────────────────────────┼────────────────────┼──────────────────────────────────────┤
  │ CNN 图像分类（ResNet/VGG 这类） │ SGD + momentum=0.9 │ 经典论文都这么做，调好后最终泛化最优 │
  ├─────────────────────────────────┼────────────────────┼──────────────────────────────────────┤
  │ Transformer / NLP / 大模型      │ AdamW              │ SGD 在 Transformer 上基本训不动      │
  ├─────────────────────────────────┼────────────────────┼──────────────────────────────────────┤
  │ 不确定、先跑通看看              │ Adam(lr=1e-3)      │ 对学习率不敏感，最省心               │
  └─────────────────────────────────┴────────────────────┴──────────────────────────────────────┘

  所以给新手的实践建议：

  - 不知道选什么就用 Adam，lr=1e-3 —— 大概率能拿到一个可用结果
  - 想榨干最后 0.2pp 且是视觉任务 —— 换 SGD+momentum，但要花时间调 lr

  这里实验选 SGD 是因为它是 AlexNet/VGG/GoogLeNet/ResNet 四篇原论文的共同配置，横向对比架构时更贴近原始设定。实验二的结果也印证了这个惯例：未调参的
  Adam（99.09%）反而输给已调好的 SGD（99.29%）。

---

### 5.3 批大小（batch size）

**是什么**：每次更新参数前看多少张图。

- 看 1 张就更新 → 噪声大，每一步都抖，但探索性强
- 看 64 张算个平均梯度再更新 → 方向更稳，但每步都是 64 张图的计算量
- 看 256 张 → 更新次数更少，更稳，但噪声也更小（噪声小不一定是好事）

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **64**（基准） | CPU 上 4 个物理核刚好能喂饱的经验值。再小的话核闲着浪费，再大 CPU 不如 GPU 受益明显。 |
| **256**（大 batch） | 想验证"增大 batch 会不会更快"。256 是 64 的 4 倍，更新次数只有 1/4，如果速度快 4 倍就赚了。 |

**特别注意**：batch size 对速度的影响在 CPU 和 GPU 上完全不同。GPU 有几千个核，大 batch 能充分利用并行；CPU 只有几个核，batch=64 已经足够喂饱，再大只是让每次矩阵乘更大，总运算量不变，不会更快。

---

### 5.4 学习率调度器（scheduler）

**是什么**：训练过程中动态调整学习率的策略。

前面说了学习率是"迈步大小"。那能不能一开始大步走（快速下山），到谷底附近改小步（精确定位）？这就是调度器做的事。

**余弦退火（Cosine Annealing）**：
- 学习率从初始值按照余弦曲线平滑地降到接近 0
- 前期 ≈ 原始学习率，中期平滑下降，后期几乎不动
- 相比"阶梯下降"（Step Decay），余弦退火没有突变，更平滑

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **无调度器**（基准） | 全程固定学习率，最朴素的对照。 |
| **cosine 退火** | 想验证"后期小学习率精修能不能提升准确率"。是业界最常用的调度策略之一，不需要额外调参（无超参数），装上就能用。 |

---

### 5.5 数据增强（data augmentation）

**是什么**：训练时对每张图做随机变换，让它看起来和原图"不一样但本质相同"。

具体来说，本实验用的增强是：
- **随机旋转**：±10° 以内随机转一下
- **随机平移**：上下左右随机挪动最多 10% 的像素

效果：训练集被瞬间放大 —— 每个 epoch 看到的都是同一批图的不同"变体"，模型不容易把训练集背下来，泛化能力更强。

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **不开**（基准） | 原始数据，最干净的对照。 |
| **开增强** | 想验证"数据增强能不能提升泛化能力"。旋转 10° + 平移 10% 是 MNIST 的常用增强幅度，太大会把 6 变成 9、把 9 变成 6，反而引入噪声。 |

**代价**：每张图都要做一次仿射变换计算，在 CPU 上会额外增加约 8% 的训练时间。

---

### 5.6 训练轮数（epochs）

**是什么**：把整个训练集完整地看多少遍。

- 第一遍看完 → 刚学了个大概，准确率可能 90%+
- 第五遍看完 → 细节更清楚了，可能到 99%
- 第二十遍看完 → 在 99% 的基础上继续精修

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **5 epochs**（实验一、二） | 作业对 MNIST 的要求通常 5 轮就够了（99%+ 很容易）。而且为了快速做超参数对比，每轮 2 分钟 × 5 轮 = 10 分钟一组，6 组 ≈ 1 小时，时间可控。 |
| **20 epochs**（实验三） | 想验证"5 轮够不够"。实验二末尾发现 `cosine` 和 `augment` 还在上升，拉长到 20 轮看它们能不能继续涨。 |

**关键发现**：5 轮时基准 99.29%，20 轮时基准 99.53%（+0.24）。意味着基准本身只是没训够，轮数拉长后 cosine 和 augment 单独的优势就消失了。

---

### 5.7 权值衰减（weight decay）

**是什么**：在损失函数里加一项"参数不要太大"的惩罚，也叫 L2 正则化。

效果：强制模型的权重不要太大，避免模型过于自信地记住训练集中的噪声。

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **0**（基准） | MNIST 本身很简单（28×28 灰度图，10 类），参数量 1.13M 的 VGG 已经够小，过拟合不严重，不需要额外正则化。实验二的结果也证实了这一点 —— 基准的 train/test gap 只有 0.54pp。 |

**为什么没单独测它**：实验二的单变量对照只测了 6 个参数，已经 1 小时了。weight decay 在 MNIST 上的影响通常很小，优先级低。

---

### 5.8 动量（momentum）

**是什么**：SGD 优化器的一个附加参数，控制"惯性"的大小。

- momentum=0 → 完全没惯性，每一步只看当前梯度
- momentum=0.9 → 当前方向 90% 来自历史方向，10% 来自新梯度

**测试值及考量**：

| 取值 | 为什么选这个 |
|------|-------------|
| **0.9**（固定） | 0.9 是业界事实标准，几乎所有 SGD 训练都用的这个值。0.8 太小感觉不到惯性，0.99 太大容易刹不住车。这不是一个需要调的参数。 |

---

### 5.9 判断流程：什么时候该调、该调什么

新手最容易犯的错是**看到 train_acc 比 test_acc 高就以为过拟合了，急着上正则化**。
实际上 gap 是最弱的信号。真正意义上的过拟合定义是：**继续训练，测试性能开始变差**。

先看曲线的走向，再决定动哪个参数：

```
测试准确率还在涨吗？（看最近 3 轮，不看单轮抖动）
  │
  ├─ 是 ──→ 继续训，别管 gap
  │
  └─ 否 ──→ 训练准确率到顶了吗？
             │
             ├─ 没到顶（train_acc 明显 < 100%，训练损失还很高）
             │    └─→ 欠拟合 / 优化没跟上，不是过拟合
             │        对策：加大模型、提高学习率、延长轮数
             │
             └─ 到顶了（train_acc ≈ 100%，训练损失趋近 0）
                  │
                  ├─ 测试稳在平台期 ──→ 到数据集天花板了
                  │     对策：换架构、加数据。正则化解决不了
                  │
                  └─ 测试持续下滑 ──→ 真过拟合
                        对策：augment / weight decay / early stopping
```

**为什么"平台期"那一支必须再看 train_acc**：测试不涨有两种完全相反的原因 ——
模型学不动（欠拟合）和模型没得学了（到顶）。两者的处方正好相反，
只看测试曲线区分不出来，必须结合 train_acc 和训练损失一起判断。

**信号可靠性排序**（从强到弱）：

| 信号 | 说明 | 本实验中的例子 |
|---|---|---|
| 1. 测试准确率见顶后持续下滑 | 最可靠，这就是过拟合的定义 | 实验二 `baseline`：e3 99.29 → e4 99.22 → e5 99.19 |
| 2. 最佳轮远早于末轮 | 说明后面的训练是白跑甚至倒退 | 实验三 `e20_cos`：最佳轮 e9，后 11 轮再没超过 |
| 3. 训练损失趋近 0 | 损失面塌平，再训只能记噪声 | 实验三 `e20_base`：末轮 0.0002 |
| 4. train/test gap 数值 | 最弱，只能横向比同类配置 | `bs256` gap +0.65 全场最高，但测试曲线单调上升，没有过拟合行为 |

**gap 的绝对值不能单独当判据**，因为同样 0.65pp 在不同场景下含义完全不同：

| 场景 | train | test | gap | 判断 |
|---|---|---|---|---|
| 本实验 `bs256` | 99.87% | 99.22% | 0.65 | 没事，错误率 0.78% 已接近 MNIST 天花板（约 99.7–99.8%） |
| 某小样本任务 | 65.0% | 64.35% | 0.65 | 也没事，两边都烂，是欠拟合 |
| 医疗影像 | 99.9% | 99.25% | 0.65 | 可能要命，取决于能否接受 0.75% 漏诊 |

**本实验的最硬证据：把 gap 修好了，准确率没涨。**
实验三 `augment` 把 gap 从 +0.49 砍到 +0.08，压掉 84% 的过拟合，
准确率只从 99.53% 涨到 99.57%（+0.04）。说明基准那 +0.49 的 gap
**根本没有让你损失准确率**。gap 存在 ≠ gap 有害。

> **本作业的结论**：11 组实验里没有一组出现明确的测试准确率下滑，
> 所以过拟合不是这个任务的主要矛盾。真正推动 99.29% → 99.67% 的是
> "训够轮数" 和 "cosine × augment 的交互"，不是 "抑制过拟合"。

---

### 理解这些参数之间的关系

5 轮实验里看似独立的参数，实际上在 20 轮实验里暴露了深层关联：

```
学习率调度器      数据增强
    ↓                ↓
  加速收敛        防止过拟合
    ↓                ↓
    合在一起才有意义：
    增强保住了损失面的坡度 → 调度器才能在后期做精修
    （单独任何一个在 20 轮下都没用）
```

这就是为什么实验二的结论（"cosine 免费提升 0.2pp"）在实验三被推翻 —— 单变量对照只能测出"每个参数独自的效果"，测不出"参数之间的相互作用"。

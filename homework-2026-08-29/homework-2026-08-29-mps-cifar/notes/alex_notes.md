# AlexNet (CIFAR-10 适配版) 学习笔记

> 对应代码：[models/alexnet.py](../models/alexnet.py)

## 问题

CIFAR-10 版本的 AlexNet 和原版不太一样：第一层卷积输出通道取 64，首两层保留 5×5（早期版本曾全部改成 3×3，后来改回核尺寸层级），并且几乎每层都加了 `BatchNorm2d`。这样调整完还算 AlexNet 吗？为什么这么改？背后的考量是什么？

## 一、它还是 AlexNet 吗？

严格来说**不是原版 AlexNet**，而是「保留 AlexNet 结构 DNA 的精简变体」。它保留了原版的几个标志性特征，所以仍属于 AlexNet 家族：

1. **5 个卷积层 + 3 层全连接**的骨架没变。
2. **中间三层连续卷积不做下采样**这个 AlexNet 最具辨识度的结构保留了 —— 见 [alexnet.py:34-42](../models/alexnet.py#L34-L42)。
3. **首两层大核的核尺寸层级**也保留了（原版 11×11 → 5×5 → 3×3×3，CIFAR 版 5×5 → 5×5 → 3×3×3）。
4. 末尾 `Dropout + 三层 FC` 的设计也保留 —— 见 [alexnet.py:46-54](../models/alexnet.py#L46-L54)。

判断标准：**结构骨架在，就是家族成员；参数和细节变了，就不是原版。**

## 二、为什么这么调整？

### 1. 首层 11×11 stride 4 → 5×5 stride 1（被迫调整，但保留核尺寸层级）

原版是为 ImageNet 的 224×224 设计的。CIFAR-10 输入只有 32×32，按原版首层计算：

```
32×32 → 11×11 stride 4 → 6×6   (一步压成)
6×6 → pool → 3×3 → pool → …   还没到 FC 就没了
```

11×11 一层就盖住输入的 1/3，后面三次 pool 直接归零，在 CIFAR 上没有生存空间。
但**不能因此把所有层都换成 3×3**——「大核 + 浅」是 AlexNet 的结构签名，全换成
3×3 就和 VGG 没了区别（最初版本就是这么改的，后来发现这会让「VGG 用堆叠小核
取代大核」这条演进主线在实验里完全不可见）。所以现在的做法是：首两层保留 5×5
（仍能讲「大核看全貌」的故事），后三层 3×3，pool 次数不变（32→16→8→4）。
`stem_kernel` 参数可在 5 / 3 之间切换，全 3×3 版本专门留作核大小对照组。

### 2. 首层通道 96 → 64（主动适配）

原版 96 是为了在 224×224 上提取丰富特征。CIFAR-10 输入只有原版的 1/49 大小（32² vs 224²），感受野覆盖范围内信息量小很多，通道数相应下调避免参数浪费。

注意是「前轻后重」的渐进式，不是一刀切：
- 第二层 192（原版 256）
- 后三层 384 / 256 / 256（基本对齐原版）

### 3. 全程加 BatchNorm2d（现代化升级）

原版用的是 **LRN（Local Response Normalization）**，那是 2012 年的方案。BatchNorm 是 2015 年提出的，现代实践里 BatchNorm 已基本取代 LRN，原因：

- LRN 需要手调超参，效果不稳定，后来证明收益有限。
- BatchNorm 自带归一化 + 轻度正则化，能让训练更稳、用更大学习率。
- 配套操作：conv 层设 `bias=False` —— 因为 BN 自带偏置项（β），conv 的 bias 冗余。

## 三、考量逻辑总结

| 调整项 | 性质 | 原因 |
|--------|------|------|
| 11×11 → 5×5（首两层） | 被迫 + 主动 | 11×11 跑不通；但保留「大核层级」这张身份证 |
| 96 → 64 通道 | 主动适配 | 小图不需要那么多通道，省参数防过拟合 |
| LRN → BatchNorm | 现代化升级 | 用 2015 年最佳实践替换 2012 年过时方案 |
| 三连续卷积不 pool | 主动保留 | AlexNet 的「身份证」，保留才算 AlexNet |

## 四、核心思路

**结构留骨、参数瘦身、训练现代化。**

把不适合小输入的部分改掉（首层卷积、通道数），把过时的训练技巧升级掉（LRN→BN），但保留网络的结构精髓（五卷积三全连接、连续卷积无 pool）。

这样既能在 CIFAR-10 上跑起来，又保留了 AlexNet 的研究价值 —— 能从训练曲线里看到 AlexNet 那种「深而窄、靠 FC 容量大」的特点。

## 五、2026-09-05 补充：5×5 vs 3×3 消融（VGG 规则的检验）

之前全部用 3×3 的适配版让 AlexNet 和 VGG 的区别只剩深度，看不出 VGG 的演进
价值在哪。现在在同一条骨架上跑了单变量对照（同通道、同 pool、同配方、同
seed，唯一变量 = 首两层核大小）：

| run | 首两层核 | 参数量 | MACs/样本 | 秒/epoch | 最优测试精度 |
|---|---|---|---|---|---|
| alexnet3x3 | 3×3 | 6.98M | 172M | 56.8 | **0.8626** |
| alexnet5x5（基线） | 5×5 | 7.18M | 225M | 68.1 | 0.8484 |

结果：**3×3 版精度更高（+1.4），参数/计算量/耗时全面更省**。这正是 VGG 论文
§2.1 的算术在数据上的验证：两层 3×3 和一层 5×5 感受野同样到 5，但参数
25C² → 18C²（-28%），ReLU 还多一次——「同样感受野，更便宜、非线性更多」。

逐 epoch 的性格差异也符合理论：第 1 个 epoch 5×5 领先（39.2% vs 35.7%，大核
开局占便宜），最后两个 epoch 3×3 拉开——小核堆叠的优势是「后劲」。

附带发现：5×5 版被 ResNet18（85.3%）反超，3×3 版（86.3%）反超回来——
「AlexNet 短周期性价比高」的一部分功劳，其实来自 VGG 式的小核适配。

完整解读见 [REPORT.md](../REPORT.md) 第二节；VGG16 自己的故事（为什么基线
垫底、lr=0.01 后 +11.5 个点）见 REPORT.md 3.2 节。

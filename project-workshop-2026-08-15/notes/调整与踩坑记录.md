## 1. 环境与依赖

### 1.1 依赖装错环境（本项目最大的坑）

**现象**：JupyterLab 运行第一个 cell `import pandas` 报 `ModuleNotFoundError`，但命令行检测显示"已安装"。

**根因**：
- `conda run -n machine-learning-aura` 里的 `pip` / `python` 实际解析到了 **pyenv 的 Python 3.10.12**（shell 路径优先级问题），包被装进了 pyenv 的 site-packages；
- 而 Jupyter 的 kernel 用的是 conda 环境自带的 **Python 3.11**，那个环境里 pandas 从未装过；
- 于是"命令行检测通过"是假象，kernel 里 import 失败。

**修复**：用 conda 环境 Python 的**绝对路径**调用 pip，确保装对地方：

```bash
/opt/anaconda3/envs/machine-learning-aura/bin/python -m pip install -r requirements.txt
```

装完后需 **JupyterLab → Kernel → Restart Kernel** 才生效。

**预防**：统一用绝对路径，或**先激活环境再装**：

```bash
conda activate machine-learning-aura
python -m pip install -r requirements.txt   # 激活后 pip 自动指向环境
```

## 4. 数据口径问题

### 4.1 三种数据粒度（补充 3.4b）

3.4 节的行级直方图（每行 = 订单中某商品）只用于**看字段本身**（清洗、log 变换决策）。补充了 3.4b 粒度对比：

| 粒度 | 每行代表 | 行数 | Quantity 均值/中位数 |
|------|---------|------|----------------------|
| 行级 | 某订单里的某商品 | 541,909 | 9.55 / 3 |
| 订单级（按 InvoiceNo 聚合） | 一次交易 | 25,900 | 199.9 / 100 |
| 客户级（按 CustomerID 聚合） | 一个客户（**RFM 粒度**） | 4,372 | 1,122.3 / 365 |

**结论**：最终聚类看**客户级**（RFM 正是该粒度）；行级分布仅用于字段清洗。直方图统一截断到 99 分位，避免极端值撑爆坐标轴。

### 4.2 清洗数字不一致：`drop_duplicates()` 的打印位置

**现象**：3.8 小结写"去重后约 392,692 行"，第 4 节输出却是 397,884。

**根因**：第 4 节 `print` 写在 `df.drop_duplicates()` **之前**——输出的是"未去重"行数；3.8 写的是去重后。差 5,192 行完全重复记录（全字段重复）。

**修复**：分两步打印，口径自洽：

```python
print("剔除脏数据后:", f"{df.shape[0]:,}", "行 |", f"{df['CustomerID'].nunique():,}", "个客户")
before_dedup = df.shape[0]
df = df.drop_duplicates()
print("去重后:", f"{df.shape[0]:,}", "行（剔除", f"{before_dedup - df.shape[0]:,}", "行完全重复）")
```

**教训**：跨 cell 引用数字时，务必标注口径（去重前/后），否则前后矛盾难排查。

### 4.3 Recency 出现 -1（时间戳问题）

**现象**：RFM 构建后 `Recency` 的 min = **-1**。

**根因**：`InvoiceDate` **含时间戳**——数据末日实际是 `2011-12-09 12:50:00`，有 1,632 行（35 个客户）是 12-09 当天的交易。而 `REF_DATE = pd.Timestamp("2011-12-09")` 是**当天零点**：

```
REF_DATE − 最后购买时刻 = 12-09 00:00 − 12-09 12:50 = −12.8 小时 → .days 取整 → -1
```

**修复**：计算前把最后购买时间 `normalize()` 归到当日零点，按**自然日**而非**时刻**计 Recency：

```python
Recency=("InvoiceDate", lambda x: (REF_DATE - x.max().normalize()).days),
```

**验证**：修复后 min = 0，无负值；Recency = 0 的 35 个客户恰为 12-09 当天购买的客户，语义正确。

**教训**：凡含时间的日期字段，做"天数差"前先想清楚要不要按自然日算；`REF_DATE` 取固定日期（当天零点）时尤其要注意。

## 8. 聚类建模与深化分析（第 7-11 节）

### 8.1 K 选择实测：肘部法 + 轮廓系数

7.1 cell 已加 **inertia 数值打印**（原来只有图，靠肉眼读拐点），重跑后逐行输出 `K=k: inertia=...  silhouette=...`。轮廓系数实测：

| K | silhouette | 说明 |
|---|-----------|------|
| 2 | 0.4340 | 全局最高，但 2 群业务区分度太粗，忽略 |
| 3 | 0.3381 | 参考基线 |
| 4 | 0.3368 | 与 K=3 几乎持平（仅差 0.001） |
| 5 | 0.3155 | 比 K=4 掉约 6.3% |
| 6 | 0.3143 | 继续降 |
| 7 | 0.3090 | — |
| 8 | 0.3021 | — |
| 9 | 0.2799 | — |
| 10 | 0.2770 | — |

**结论**：K=3→4 质量无损、K=5 起明显下滑，**K=4 是性价比拐点**，`K_BEST = 4`。inertia 的拐点也落在 4 附近，两指标互相印证。

### 8.2 DBSCAN 选型失败（结构性不适用）

- eps=0.6 只分出 **1 簇 + 43 噪声**，其 0.552 的轮廓系数是**"单簇假象"**（没有划分谈何质量），ARI / NMI = 0 印证标签无信息；
- eps 扫描：eps=0.2 碎成 **39 簇 + 14.5% 噪声**，eps=0.5 时 4 簇，eps=0.6 塌缩成 1 簇——**无稳定平台**；
- **根因**：RFM 空间密度均匀连续，客户呈"层级型"渐变分布，DBSCAN 依赖密度断裂，天然不适用；单簇时 DBI 定义退化（分子分母都指向簇内），数值不可比。

**教训**：DBSCAN 不是"参数没调好"，是**算法与数据分布不匹配**，换 eps 只是徒劳。遇到"密度连续"应先怀疑选型而非调参。

### 8.3 结果质量评估（K-means K=4）

| 指标 | 数值 | 判定 |
|------|------|------|
| 轮廓系数 | 0.337 | 中等偏弱（簇边界模糊、连续渐变） |
| DBI | 1.01 | 可接受 |
| CH | 3,299.86 | 较好 |
| 簇大小 | 699 / 1,635 / 826 / 1,178 | 无病态小簇 |

**总体判断**：K-means 是**可用但不算理想的基线**。

## 9. 优化实验（notebooks/optimization.ipynb，2026-08-19）

针对 8.6 改进方向挑选 5 个点逐项实测，数据口径与 `analysis.ipynb` 完全一致（541,909 → 397,884 → 392,692 / 4,338 客户 / 18,532 订单）。**所有数字均来自真实数据复跑（notebook 已从头执行验证通过）。**

### 9.1 特征扩展（7 维）——反直觉结果

| 方案 | K=4 silhouette | 最优 K | 最优 silhouette |
|---|---|---|---|
| 原始 RFM（3 维） | 0.3368 | 4 | 0.3368 |
| 扩展（7 维） | **0.2759（↓）** | **3** | **0.3796（↑）** |

- K=4 原地指标下降，根因：**高维惩罚** + **冗余特征**（`AvgOrderValue`×`Monetary` 相关 0.709、`UniqueStock`×`Frequency` 相关 0.623），欧氏距离重复计入重叠信息；
- 真正信号：**扩展后最优 K 从 4 移到 3**——扩展的价值体现在改变/明确了最优结构，而非原地提升 K=4 指标。

### 9.2 Monetary Winsorize（99 分位 = 19,780，截断 44 人）

- 前后 **ARI=0.993**、轮廓 0.276 → 0.277、簇大小几乎一致——**分群几乎不变**；
- 根因：`log1p` 已把 28 万极端值压到 ~13，极端客户对簇中心影响本就有限；
- **结论：原模型对极端值已稳健，Winsorize 收益甚微**（可做但不应期待改变结论）。

### 9.3 K=3/4/5/6 画像与业务解释力对比

| K | silhouette | 簇大小 | 业务解读 |
|---|---|---|---|
| 3 | **0.3796** | 2313 / 1880 / 145 | 沉睡 / **活跃高价值**（22 天·5 单·1,839 元）/ 中间小簇——最清晰 |
| 4 | 0.2759 | 1067 / 1824 / 140 / 1307 | 中间层被拆，140 人小簇仍存在 |
| 5 | 0.2515 | 1002 / 711 / 1301 / 1213 / 111 | 额外识别**顶级客户**（8 天·10 单·3,963 元），适合 VIP 运营 |
| 6 | 0.2351 | 6 簇 | 继续细分，性价比递减 |

**没有明显赢家**：追求指标选 K=3，关注 VIP 运营可看 K=5，K=4 相对居中——印证 8.6 中"K 的选择本质是业务取舍"。

### 9.4 RFM 经典 5 档交叉验证（125 种组合）

- ARI=0.067 / NMI=0.300 **数值很低，主因是粒度差异**（4 簇 vs 125 档，差约 30 倍），ARI 不适合直接比较"4 簇 vs 125 档"；
- 看业务自洽性：簇1 = **R4/F4/M4**（近 22 天·5 单·1,837 元，高价值活跃）、簇0 = **R2/F2/M1**（138 天·1 单·179 元，沉睡低值）——**序关系完全说得通**；
- 结论：二者序关系一致、互为校验；K-means 保留连续距离的中间细节，不宜互相替代。

### 9.5 PCA / 特征相关性（改进点 5）

- **`Frequency`×`Monetary` 相关 0.808**（买得勤通常花得多，证实原判断）；
- **PCA**：5 主成分保留 **95.7%** 方差，PCA 后分群与原标签 **ARI=0.990**——不改变分群实质，属"锦上添花"，更大价值在 PC1~PC2 散点可视化（保留 ~67% 方差）辅助展示，非必需步骤。

### 9.6 优化实验小结

- 核心业务结论在**所有方案下一致**：高价值簇 = 近购 + 高频 + 高额；
- 建议二选一：与既有分析保持一致用 **RFM K=4**；追求指标与画像简洁用 **扩展特征 K=3**；
- 极端值处理与 PCA 均非必需（`log1p` + 原特征已足够稳健）。

### 9.7 教训（本轮新增）

- **特征扩展 ≠ 指标必然提升**：维度增加会稀释欧氏距离，冗余特征重复计入相似度；扩展前应先看相关矩阵诊断；
- **ARI 不能跨粒度比较**：4 簇 vs 125 档的 ARI=0.067 易被误读为"不一致"，实际序关系完全自洽——先看业务自洽性，再谈数值；
- **稳健性检验要看 ARI**：Winsorize 前后用 ARI（0.993）判断"分群是否实质变化"，比只看轮廓系数微变更有意义。

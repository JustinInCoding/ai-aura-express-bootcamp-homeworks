> 数据来源：英国某在线零售商 2010-12-01 至 2011-12-09 全部交易记录
> 说明：以下所有统计均为对 `data/OnlineRetail.csv` 实际探查结果。

## 三、各特征详细说明

### 1. InvoiceNo（发票编号）

- **类型**：object（类别文本），无缺失
- **示例**：`536365`、`536366`、`C536379`
- **关键规则**：
  - 6 位纯数字：正常销售发票；
  - **以 "C" 开头**：取消/退回的订单发票，共 **9,288 行**，计算时需剔除；
  - 去重后有 25,900 张发票。
- **聚类用途**：Frequency 的计算依据——统计每个 CustomerID 的去重发票数。

### 2. StockCode（商品库存代码）

- **类型**：object（类别文本），无缺失
- **示例**：`85123A`、`71053`、`84406B`
- **去重数**：4,070
- **说明**：每行一笔交易明细，同一发票下可含多个不同 StockCode。
- **聚类用途**：本项目主流程不直接使用；可扩展计算「购买品类/商品多样性」作为额外客户特征（见项目展望）。

### 3. Description（商品描述）

- **类型**：object（文本），**缺失 1,454 行（0.27%）**
- **示例**：`WHITE HANGING HEART T-LIGHT HOLDER`
- **说明**：部分记录缺失（主要是 StockCode 为 `POST` 邮费、`DOT` 等服务类条目），不影响 RFM 构建。
- **聚类用途**：本项目不使用（文本特征需 NLP 处理，超出范围）。

### 4. Quantity（数量）

- **类型**：int64，无缺失
- **统计**：

| 指标 | 值 |
|------|-----|
| 均值 | 9.55 |
| 中位数 | 3 |
| 最小值 | **-80,995** |
| 最大值 | **80,995** |
| 负值行数 | **10,624（1.96%）** |

- **关键规则**：
  - **负值 = 退货**，共 10,624 行，RFM 构建前剔除；
  - 存在极端值 ±80,995（单笔大宗订单），对金额统计影响大，需在 EDA 中检查。
- **聚类用途**：与 UnitPrice 相乘得到单笔金额 `Amount = Quantity × UnitPrice`。

### 5. InvoiceDate（交易时间）

- **类型**：object（原始为字符串 `m/d/yyyy H:MM`），无缺失
- **时间跨度**：2010-12-01 08:26 至 2011-12-09 12:50
- **去重数**：23,260（说明同一分钟多笔交易、且时间粒度到分钟）
- **聚类用途**：
  - 计算 **Recency**：`基准日(2011-12-09) − 客户最后购买日`；
  - 可扩展做月度/季度行为演变分析（项目展望部分）。

### 6. UnitPrice（单价）

- **类型**：float64，无缺失
- **统计**：

| 指标 | 值 |
|------|-----|
| 均值 | 4.61（£） |
| 中位数 | 2.08 |
| 最小值 | **-11,062.06** |
| 最大值 | **38,970** |
| ≤0 行数 | **2,517（0.46%）** |

- **关键规则**：
  - **≤0 的单价是错误/调整记录**（负值多为取消调整、0 多为赠品），共 2,517 行，RFM 构建前剔除；
  - 出现 38,970 英镑的高单价商品（大件/定制商品），属于合法数据，保留但需在 EDA 中标注。
- **聚类用途**：与 Quantity 相乘得金额，参与 Monetary 计算。

### 7. CustomerID（客户编号）

- **类型**：object（5 位数字），**缺失 135,080 行（24.93%）**
- **去重数**：**4,372**（即有效客户数）
- **关键规则**：
  - 缺失 CustomerID 的订单无法关联客户，**直接剔除**（约 135,080 行）；
  - 缺失原因通常是未登录访客下单（英国数据集中常见现象）。
- **聚类用途**：**RFM 聚合的唯一主键**——所有特征工程都围绕该字段 `groupby` 展开。

### 8. Country（国家）

- **类型**：object（类别文本），无缺失
- **去重数**：38
- **分布（Top 10）**：

| 国家 | 行数 | 占比 |
|------|------|------|
| United Kingdom | 495,478 | 91.4% |
| Germany | 9,495 | 1.75% |
| France | 8,557 | 1.58% |
| EIRE（爱尔兰） | 8,196 | 1.51% |
| Spain | 2,533 | 0.47% |
| Netherlands | 2,371 | 0.44% |
| Belgium | 2,069 | 0.38% |
| Switzerland | 2,002 | 0.37% |
| Portugal | 1,519 | 0.28% |
| Australia | 1,259 | 0.23% |

- **说明**：英国本土占绝对主导（91.4%），其余 37 国合计仅 8.6%，存在明显不平衡。
- **聚类用途**：主流程不使用（避免地区不平衡影响聚类）；可扩展用作**业务伪标签**（如 UK vs 海外）做 ARI/NMI 外部验证。

## 四、数据质量总结（对聚类项目的直接影响）

| 数据问题 | 规模 | 处理方式 | 影响 |
|----------|------|----------|------|
| CustomerID 缺失 | 135,080 行（24.93%） | 直接剔除 | 有效交易约 406,829 行，客户 4,372 个 |
| Description 缺失 | 1,454 行（0.27%） | 无需处理（不使用该字段） | 无影响 |
| Quantity 为负（退货） | 10,624 行（1.96%） | 剔除 Quantity ≤ 0 | 避免退货虚增金额 |
| UnitPrice ≤ 0 | 2,517 行（0.46%） | 剔除 UnitPrice ≤ 0 | 避免错误/赠品记录 |
| C 开头取消发票 | 9,288 行（1.71%） | 剔除 | 避免取消单污染 F/M |
| Quantity 极端值 ±80,995 | 个别行 | EDA 检查后保留或剔除 | 影响 M 分布，需标准化/对数变换 |
| 高单价 38,970£ | 个别行 | 保留（合法数据） | 同上 |
| 国家极度不平衡（UK 91.4%） | — | 主流程不使用 Country | 避免聚类偏向 |

**清洗后的预期数据量**：约 397,000+ 行有效交易 → 聚合为 **4,372 客户 × RFM(3 维)** 特征矩阵。

---

## 五、与聚类流程的对应关系

```
InvoiceNo ──► F 频率（去重发票计数）
InvoiceDate ──► R 最近购买（距 2011-12-09 天数）
Quantity × UnitPrice ──► M 消费金额（按客户求和）
CustomerID ──► 聚合主键
（剔除：CustomerID 缺失 / Quantity ≤ 0 / UnitPrice ≤ 0 / C 开头取消单）
```

> 注：上表"有效客户 4,372 个"为原始数据实测值；若同时剔除退货与取消单，最终客户数可能略少（约 4,000 上下），以清洗后实际结果为准。

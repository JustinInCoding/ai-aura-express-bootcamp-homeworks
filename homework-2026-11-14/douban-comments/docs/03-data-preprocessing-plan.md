# 数据预处理方案（依据 EDA 结果规划）

> 输入：`01_eda.ipynb` 的全部统计结论（下文以 §N 引用 notebook 章节）。
> 目标：为「评论打分模型」（见 `02-rating-model-plan.md`）产出一份干净、可直接建模的数据集。
> 三条主线对应用户诉求：**去掉没用的数据**（§3）、**修正不好的数据**（§4）、**补充不够的数据**（§5）。

## 1. 总原则

1. **每一剔除动作都可量化、可回溯**：管道中每一步打印「before → after」行数，剔除原因落盘到 `output/clean_report.json`；
2. **清洗动作区分"必做"与"消融验证"**：影响样本量大的动作（如长度过滤）先做标记列，是否真正剔除交给建模阶段的消融实验；
3. **只依赖 comments.csv 建模**：movies.csv 仅在需要电影名展示时 join，不因 join 失败而丢弃评论（这是 EDA 清洗逻辑与本方案的最大差异，见 §3.1）。

## 3. 去掉没用的数据

### 3.1 匹配不到电影的评论：**不再剔除，改为标记**（重要修正）

EDA 版把 NAME 缺失（MOVIEID 匹配不到 movies.csv）的 26% 记录全部剔除了。但：

- 建模输入是「CONTENT → RATING」，电影名只是展示性元数据；
- 一刀切丢掉 10 万+ 条带标签样本，代价远大于收益。

**处理**：保留这些记录，加一列 `HAS_META`（True/False）。仅当后续做"电影级聚合分析"时才用 `HAS_META == True` 子集。

### 3.2 目标变量与文本不可用的记录（必做）

- RATING 为 NaN 或不在 [1,5]：1,137 条，目标变量缺失无法补救，剔除；
- CONTENT 为空、纯空白、**纯标点/纯符号**（如「。。。」「！！！」）：正则 `^[\W_]+$` 识别后剔除。EDA 未单独统计此类，管道中补计数。

### 3.3 重复数据（必做，两级去重）

| 层级 | 键 | 规则 | EDA 依据 |
|---|---|---|---|
| 行级 | 整行完全相同 | 剔除 | §1.2：11 条 |
| 用户×电影级 | (CREATOR, MOVIEID) | 保留 TIME 最新一条 | §1.2：约 2.2 万条 |

- 保留最新而非最短：同一用户修改/追评后最新文本最能代表其最终评价；
- 注意：`02-rating-model-plan.md` §2.1 与此规则一致。

### 3.4 疑似机器人/灌水用户（必做，阈值驱动的剔除）

§5 显示头部用户高达 2,989 条评论，且「无聊」「不喜欢」等 2~4 字评论被重复数百次——高度疑似刷评账号。处理：

1. 统计每用户评论数与平均长度，标记 `comments > 50 且平均长度 < 10 字` 的用户为疑似机器人；
2. 在清洗报告里输出该群体的规模、其评级的分布（若集中打同一星级，坐实灌水）；
3. 剔除该群体（预计数千条）；阈值在管道中做成参数，供消融。

### 3.5 无信息量字段（必做）

- 丢弃 `ADD_TIME` 列：1,572 个唯一值的爬取快照时间，对建模无意义且易误用；
- 丢弃 EDA 过程列（TOKENS、LEN_BUCKET 等临时列），仅保留派生特征。

### 3.6 超短文本：**不直接剔除，降权 + 消融**（消融验证）

<20 字占 38.3%，直接剔除会损失近四成数据。策略：

- 打标记列 `IS_SHORT = (LEN < 20)`；
- 训练时对 `LEN < 5` 的极端短评降权或剔除（与 `02-rating-model-plan.md` §2.1 的消融设计对接）；
- 5~20 字短评保留：EDA §3.1 箱线图显示长度本身与星级相关（星级越极端文本越短/越长均有信号），短评并非无信号。

### 3.7 缺失值处理汇总（必做，按字段）

EDA §1.1 实测各字段缺失率均 < 0.2%，但处理策略因字段角色而异。总原则：**文本与目标变量绝不插补**（插补 = 造标签/造语料），结构化派生特征的缺失用冷启动默认值兜底（见 §5.2）。

| 字段 | 缺失数（EDA） | 角色 | 处理 |
|---|---|---|---|
| ID | 11 | 行主键 | 剔除（无法追溯） |
| TIME | 54 | 去重键 + 派生特征 | 剔除（去重"保留最新"与 YEAR 切分都依赖它） |
| MOVIEID | 111 | join 键 | 保留，`HAS_META=False`；不参与电影级聚合（见 §3.1） |
| RATING | 111（NaN 共 1,137） | 目标变量 | 剔除（见 §3.2，不可插补） |
| CONTENT | 141 | 模型输入 | 剔除（见 §3.2，不可插补） |
| **CREATOR** | **691** | 去重键 + 用户特征 | **不剔除**（文本+标签仍可用）；特殊处理见下 |
| ADD_TIME | 168 | 无用列 | 整列丢弃（§3.5），缺失无关紧要 |

**CREATOR 缺失的连锁问题**（EDA 未暴露，本方案必须显式处理）：

1. **去重失效**：pandas 中 `NaN != NaN`，`(CREATOR, MOVIEID)` 去重会对缺失行全部"去不了重"——这些行原样保留全部 691 条，不参与用户级去重，管道中打印计数；
2. **不要填哨兵值做去重键**：若把缺失 CREATOR 统一填成 `'_anon_'`，690 个互不相识的匿名用户会被当成同一个 key 而被错误去重；
3. **USER_MEAN_RATING 冷启动**：CREATOR 缺失的行直接用全局均值（与 §5.2 的冷启动规则一致）。

## 4. 修正不好的数据

### 4.1 编码与类型（必做）

| 问题 | 修正 |
|---|---|
| movies.csv 为 GBK，个别行可能 gb18030 才能读 | 读取时 gbk → gb18030 回退（沿用 EDA 做法），并断言 NAME 无乱码（抽查 10 行） |
| MOVIEID 被读成字符串、movies.ID 是 int64 | 统一 `pd.to_numeric(errors='coerce').astype('Int64')`（EDA 已复现此坑） |
| TIME 为字符串 `2015/6/10 2:45` | `pd.to_datetime(format='%Y/%m/%d %H:%M', errors='coerce')`，解析失败的剔除（约 54 条 TIME 本身缺失） |

### 4.2 movies.ID 重复导致的 join 扇出（必做，EDA 隐藏 bug）

EDA 中 merge 后行数 405,083 → 405,863，**多出 780 行**，说明 movies.csv 的 ID 有重复，left join 把部分评论复制了多份。这些复制行会同时参与训练（同文本同星级重复计入），必须修：

1. `movies.drop_duplicates(subset='ID', keep='first')` 后再 join；
2. 在清洗报告中记录 join 前后行数，断言 `len(after) == len(before)`。

### 4.3 NLP 专有文本清洗（必做，按 EDA §3.2 的实测占比排序）

| 规则 | 依据 | 动作 |
|---|---|---|
| 去多余空白/连续换行 | 抽样可见大量不规则空格 | 合并为单个空格，strip |
| 不可见字符清理 | 爬取文本常见 | 删除零宽字符（U+200B 等）、控制字符、BOM |
| 全角/半角统一 | 中英混排评论常见全角字母数字 | 仅对**字母/数字**做全角→半角（`ＥＮ`→`EN`、`１２３`→`123`）；中文标点保留原样（「！！」是语气信号） |
| 英文大小写 | 纯英文评论占 3.05% | 仅 baseline 路线 lowercase；RoBERTa 路线保留原大小写 |
| 数字处理 | 5 星样本中出现「95/100」式打分 | **保留数字**（带分值的评论有强信号），不做数字化简 |
| 压缩重复标点 | 「。。。。。。」「！！！！」大量出现 | 连续相同标点压缩到 2 个（保留语气信号，不全部删除） |
| URL 移除 | 0.193% 含 URL | 正则替换为空串 |
| HTML 转义还原 | 0.001% | `html.unescape` |
| @用户 移除 | 0.277% | 正则替换为空串 |
| emoji | 0.261% | **保留**（表情有情感极性，如 😂）；RoBERTa 分词器可处理，词袋方案中自然被过滤 |
| 繁简转换 | 3 星残留单元格、4/5 星均有繁体评论 | `opencc` 统一转简体（繁体词在词袋里被当成不同 token，如「確實/确实」分裂计数）；打 `IS_TRAD` 标记留档 |
| 「剧透」标记 | 0.172% 含"剧透"字样 | 不删文本，打 `HAS_SPOILER` 标记，供误差分析 |

> 清洗只做"无损规范化"：所有会改变语义边界的信息（emoji、繁体）先标记再决定，不做激进删除。

### 4.4 3 星样本异常问题（必做调查 + 建模对策）

原始 3,029 条 3 星 → 清洗后占比 0.0%，几乎全部在 EDA 清洗中被过滤。这说明**3 星记录与"脏数据"高度共现**（大量为纯英文、繁体、无匹配电影），是数据源本身的采集/编码 quirk，不是真实分布。处理：

1. **调查**：单独抽取全部 3 星记录，统计其 CONTENT 缺失率、纯英文率、MOVIEID 匹配率，确认结论；
2. **建模对策**（与 `02-rating-model-plan.md` §2.3 对接）：
   - 默认按 **4 类（1/2/4/5 星）有序分类**处理，文档中明确说明 3 星不可用；
   - 不做"把 3 星从 2/4 星中插值造出来"之类的合成——会注入虚假标签；
   - 评估时明确"本模型不预测 3 星"的口径，避免与外部结果不可比。

### 4.5 异常值检测（必做，规则式，标记优先）

数据规模 40 万条、维度低，**不需要** IsolationForest/LOF 等模型式异常检测，规则式检查 + 报告即可。原则：先标记进清洗报告，剔除必须有明确阈值依据。

| 检查项 | EDA 依据 | 规则与处理 |
|---|---|---|
| 评论长度极端值 | §3.1：max 4,244 vs P99=149 | **不剔除**（长评有信号），截断到 512 字（覆盖 RoBERTa max_len 128 token 绰绰有余），打 `IS_LEN_OUTLIER` 标记 |
| TIME 越界 | §1.1：快照日 2018-01-23 | 解析后断言 `TIME <= 快照日`；晚于快照日的"未来评论"是脏数据，剔除并计数；早于 2005-01-01（豆瓣上线年）同样剔除 |
| RATING 越界 | §1.1：实测无 | EDA 已确认只有整数 1~5，管道保留断言兜底（防上游数据变更） |
| 评分-文本极性矛盾 | §7.3 反讽样本 | 粗规则抽检（如 5 星但「烂片/垃圾」出现 ≥2 次）打 `POLARITY_CONFLICT` 标记，仅供误差分析，不剔除——反讽是真实语言现象（与方案 §6 风险表一致） |
| 机器人用户 | §5：头部 2,989 条 | 见 §3.4，不在此重复 |
| movies.ID 重复 | §0：join 扇出 +780 行 | 见 §4.2，不在此重复 |

### 4.6 分词处理（补充，仅词袋 baseline 路线需要）

分词消费方只有 TF-IDF/fastText 等 baseline 特征；**RoBERTa 微调路线用原文，不做 jieba**（与 `02-rating-model-plan.md` §3.1 的三级特征表对应）。

| 项 | 规则 | 依据 |
|---|---|---|
| 分词器 | jieba（`HMM=True`） | EDA §7.1 已验证可行 |
| 自定义词典 | 加入领域词：「服化道」「烂片」「刷分」「无剧透」等 jieba 默认切开的词；电影名不加入（电影名不在评论高频词表且会随数据集过时） | EDA 分词示例把「服化道」切成了「服化/道」 |
| 过滤时机 | 长度 >1 的过滤**不在分词阶段做**，挪到停用词阶段统一处理（避免把「不」「没」这类关键单字在错误环节丢掉） | EDA §7.2：否定结构必须保留给 bigram |
| 产物 | `TOKENS` 列（list[str]），仅 baseline 消费；bigram 在特征工程阶段由 TOKENS 生成 | 对接方案 §3.1 |
| 输出格式 | CSV 中 TOKENS 序列化会破坏可读性 → baseline 管道改为在内存中现算，`cleaned_comments_v2.csv` 不落盘 TOKENS | 保持主文件干净 |

### 4.7 停用词过滤（补充，仅词袋 baseline 路线需要）

| 项 | 规则 | 依据 |
|---|---|---|
| 词表来源 | 以 EDA §7.1 的 `STOPWORDS` 为基础，补充：标点、单字英文字母、纯数字 token、豆瓣语境通用词 | EDA 词表已含「电影/影片/片子」等 |
| **否定词豁免（关键）** | 「不」「没」「无」「别」「莫」**必须从停用词中排除**，并确保它们能进入 bigram | EDA §7.2：1 星富集 bigram「完全没有」「实在看不下去」——丢否定词会把「不好看」变成「好看」，直接翻转标签信号 |
| 词表固化 | 在**训练集上**统计后固化为 `output/stopwords.txt`，train/val/test 用同一份 | 防止验证集信息泄入预处理 |
| RoBERTa 路线 | 不做停用词过滤 | 预训练模型自带子词切分，过滤反而伤语义 |
| 验收 | 断言「不」「没」不在最终词表中 | 对接 §7 验收清单 |

## 5. 补充不够的数据

"补充"分三类：**补不回来的**（明说不补）、**用特征补的**、**用采样策略补的**。

### 5.1 无法或不应补充的

| 缺口 | 决策 | 理由 |
|---|---|---|
| RATING 缺失（1,137 条） | 剔除，不补 | 目标变量缺失，插补等于造标签 |
| 3 星样本（≈0 条） | 不造数据，改 4 类口径 | 见 §4.4 |
| 纯英文/外语评论（3.05%） | 保留不删 | 打标记，RoBERTa 有一定英文能力；词袋方案中可在误差分析单独报告 |

### 5.2 用派生特征补足信号（必做）

| 新列 | 定义 | 泄漏防护 |
|---|---|---|
| `LEN` / `N_TOKENS` | 字符数 / jieba 词数 | 无 |
| `YEAR`, `MONTH` | 评论发布年月 | 无 |
| `IS_SHORT`, `IS_PURE_EN`, `IS_TRAD`, `HAS_SPOILER`, `HAS_META` | §3/§4 的标记列 | 无 |
| `USER_MEAN_RATING` | 该用户在**训练集内**的历史评分均值，冷启动填全局均值 | 只用训练集统计（与方案 §3.2 一致） |
| `MOVIE_BAYES_MEAN` | 电影贝叶斯平均分 `（m·C + 全局均值）/（m + C）`，C 为先验强度 | 只用训练集统计；解决长尾电影均值不可靠（§2.2） |

### 5.3 用采样/权重补类别失衡（训练阶段，非本管道）

清洗后实际分布约为 2 星 39%、4 星 38%、5 星 25%、1 星 10%（归一化到 4 类后），失衡比 ≈ 4:1，比 EDA 表面的 3447:1 温和得多（那个数字是被 3 星≈0 拉爆的）：

- 默认类别权重（weighted CE / class weight）；
- 1 星作为最稀缺且业务上重要的类，训练集内可小幅过采样（仅 train，val/test 永远保持真实分布）；
- 评估主指标用 macro-MAE / macro-F1（与方案 §5.1 一致）。

### 5.4 数据增强（可选，明确不推荐为默认）

短文本回译/同义替换对 1 星类别的增益不确定，且豆瓣短评本身高度口语化、增强易失真。列为可选实验，不进主管道。

## 7. 验收清单（管道末尾自动断言）

1. join 后行数 == join 前行数（无扇出）；
2. `RATING ∈ {1,2,4,5}`，无 NaN；
3. 无整行重复、无 (CREATOR, MOVIEID) 重复；CREATOR 缺失的行不参与用户级去重且数量在报告中单独打印；
4. `CONTENT_CLEAN` 无空串、无 URL、无零宽字符、无全角字母数字、无连续 >2 的重复标点；
5. `LEN > 0` 全部成立；`TIME` 全部落在 [2005-01-01, 快照日] 区间内；
6. 各星级占比打印并与本方案 §5.3 预期核对；
7. 清洗报告 JSON 落盘且各步骤行数守恒（每步 after = 下一步 before）；
8. 若走 baseline 路线：`stopwords.txt` 存在，且「不」「没」「无」「别」不在词表中（否定词豁免，见 §4.7）。

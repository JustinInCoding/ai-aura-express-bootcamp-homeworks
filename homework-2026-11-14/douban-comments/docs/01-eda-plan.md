# 豆瓣电影评论数据集 EDA 方案

> 目标：从统计与可视化两个方向全面展示数据的分布情况，为后续"评论打分模型"的设计提供数据依据。
> 数据文件：`dataset/comments.csv`（约 42.4 万条评论，UTF-8）、`dataset/movies.csv`（约 9373 部电影，**GBK 编码**）。

## 0. 数据加载与前置处理

### 字段结构

| 文件 | 字段 | 说明 |
|---|---|---|
| comments.csv | ID | 评论 ID |
| | TIME | 评论发布时间（如 `2015/6/10 2:45`） |
| | MOVIEID | 关联 movies.csv 的 ID |
| | RATING | 用户评分（1~5 星）⭐ 打分模型的目标变量 |
| | CONTENT | 评论正文 ⭐ 打分模型的输入特征 |
| | CREATOR | 评论者昵称 |
| | ADD_TIME | 数据采集时间（本数据集内多为同一批量采集时间，信息量低） |
| movies.csv | ID / NAME | 电影 ID 与名称（**GBK 编码，读取时需指定 `encoding="gbk"`**） |

### 前置处理要点

- movies.csv 用 `encoding="gbk"`（如失败再尝试 `gb18030`）读取；comments.csv 用 UTF-8。
- 两表以 `MOVIEID = ID` 做 left join，给每条评论补上电影名。
- 统一剔除：RATING 为空/超出 [1,5] 的记录、CONTENT 为空的记录、MOVIEID 无法匹配电影的评论。

## 1. 数据质量检查（EDA 的第一步）

### 1.1 缺失值与异常值统计

- **展示方式**：各字段缺失数量/缺失率的条形图 + 数据类型表。
- **分析要点**：
  - RATING、CONTENT 的缺失率直接决定建模可用样本量；
  - ADD_TIME 若 99% 相同，说明是一次性爬取快照，后续时间分析只用 TIME；
  - 检查 RATING 是否存在 0、6、小数等异常值（豆瓣有"半星"习惯，确认本数据集是否已取整）。

### 1.2 重复数据

- **展示方式**：完全重复行数、`(CREATOR, MOVIEID)` 重复对数、`(CONTENT)` 重复的条数统计表。
- **分析要点**：
  - 同一用户对同一电影的多条评论可能是"短评+修改"痕迹，建模前需决定保留哪条；
  - 大量相同文本（如"好片""垃圾"）说明语料有大量低信息量评论，会影响模型学到的信号。

---

## 2. 目标变量分布：RATING（最重要的一张图）

### 2.1 评分分布

- **统计**：1~5 星各自的条数、占比、均值、中位数、众数。
- **可视化**：RATING 的柱状图（标注百分比），可再叠一个累计分布曲线。
- **分析要点**：
  - 豆瓣评论典型呈 **J 型分布**：1 星与 5 星远多于中间分（用户只有在极端爱/恨时才写评论）。若确认如此，说明存在**选择偏差**——模型学的是"写评论的人的评分"，不是全体观众的评分；
  - 类别不平衡程度（如 1 星占比 vs 3 星占比）直接决定建模时是否需要重采样/类别权重；
  - 3 星（中间档）若最少，提示"区分 2/3/4 星"是模型最难的部分。

### 2.2 每部电影的整体评分水平

- **统计**：每部电影评论数、评分均值/中位数/标准差的描述统计。
- **可视化**：
  - 电影平均分的直方图；
  - 评论数 Top 20 电影的横向条形图（附平均分标签）。
- **分析要点**：
  - 电影平均分多集中在哪一区间，方差大的电影（评分两极分化，如粉丝向/争议片）是哪些；
  - Top 评论量的电影是否集中在少数热门大片——**长尾分布**意味着大部分电影只有几十条评论，"按电影聚合"的特征对长尾电影不可靠。

---

## 3. 文本基本特征分布：CONTENT

### 3.1 评论长度分布

- **统计**：字符数（或分词后词数）的均值、中位数、P90/P99、最短/最长。
- **可视化**：评论长度直方图（长尾建议用 log 刻度或截断显示）；**按 RATING 分组的箱线图 / 小提琴图**。
- **分析要点**：
  - 短评（<20 字）占比高是豆瓣短评的典型特征，"呃""好片"这类超短文本对文本模型几乎没有信号，可考虑设最小长度过滤；
  - 对比各评分组的长度：若 1 星评论显著更长（吐槽欲更强）或 5 星更短（"神作"二字足矣），说明长度本身就有一定预测力，可作为辅助特征。

### 3.2 文本内容质量

- **展示方式**：含 emoji/表情符号、纯英文、含 URL、含"剧透"字样的评论占比表；随机抽样 20 条不同评分的评论人工阅读。
- **分析要点**：
  - 是否需要清洗（URL、@ 用户、HTML 转义符）；
  - 抽样阅读能提前感受各星级评论的语言风格差异，为后面"分星级词云"建立直觉。

---

## 4. 时间维度分布

### 4.1 评论的时间趋势

- **可视化**：按年/月的评论量折线图；同一图上用不同颜色叠 1 星、3 星、5 星评论量趋势。
- **分析要点**：
  - 评论通常集中在电影上映后 1~3 个月内（爬取的是"热评页"则更集中）；
  - 对比好评/差评随时间的走势：差评是否在口碑反转的电影上滞后出现（"高开低走"现象）。

### 4.2 评分与评论时间的关系

- **可视化**：按"上映后第 N 月"分桶的各星级占比堆叠面积图（若有电影上映时间可用；不可用则按评论年份分组看各星级占比变化）。
- **分析要点**：
  - 早期评论与晚期评论的星级分布差异，反映口碑演化；
  - 若不同年份星级占比系统性漂移（如近年 1 星变多），说明存在**时间混杂因素**，建模时要做按时间切分的验证（见模型方案）。

---

## 5. 用户维度分布

- **统计**：评论数 Top 20 用户、每个用户评论数的分布（人均条数、中位数、最大值）。
- **可视化**：用户评论数的对数-对数分布图（幂律/长尾）；Top 用户柱状图。
- **分析要点**：
  - 是否存在刷评论机器人（同一用户短时间大量评论，评论数分布异常突出的头部）；
  - 头部活跃用户的评分习惯是否偏严/偏松——同一用户内评分方差与整体方差对比；
  - 若刷号明显，数据清洗时要剔除。

---

## 6. 电影维度交叉分析

### 6.1 电影 × 评分

- **可视化**：
  - 评论数 Top 10 电影的**评分分布堆叠条形图**（每部电影一行，显示 1~5 星构成）；
  - 电影"评论数 vs 平均分"散点图（点大小 = 评分标准差）。
- **分析要点**：
  - 直观看到哪部电影两极分化（1 星和 5 星同时高）、哪部电影一边倒；
  - 散点图上评论数与平均分的相关性：样本少的小样本电影平均分波动更大（回归到均值现象）。

### 6.2 星级 × 评论长度的热力图

- **可视化**：横轴 RATING（1~5），纵轴评论长度分桶，颜色为占比的热力图。
- **分析要点**：长度与星级是否相关、交互关系如何，为模型特征工程提供依据。

---

## 7. 文本内容分析（面向打分模型的关键环节）

### 7.1 分星级高频词

- **统计**：jieba 分词 + 停用词过滤后，各星级 Top 30 高频词表；进一步计算 **TF-IDF 加权的"星级区分词"**（在某星级内显著富集的词，可用 log-odds ratio 或卡方检验排序）。
- **可视化**：5 张分星级词云；一张"区分词"双向条形图（左=1 星富集词，右=5 星富集词）。
- **分析要点**：
  - 直接验证"文本可预测星级"这一建模前提：若 1 星富集词是「烂/失望/垃圾/难看」、5 星是「经典/感动/神作」，则任务可行性成立；
  - 中间星级（3 星）区分词弱、语义含糊（"还行""一般"），预示中间档是模型误差主要来源；
  - 反讽/网络用语（"绝了""细思极恐"） sentiment 方向依赖上下文，是纯词袋模型的盲区。

### 7.2 N-gram 与句式

- **展示方式**：各星级 Top 20 二元组（bigram）表。
- **分析要点**：词袋丢掉的搭配（"不 好看" vs "好看"）在 bigram 中是否大量出现，决定分词/特征方案是否需要保留否定结构。

### 7.3 每部电影内部的文本-评分一致性

- **展示方式**：选 3 部口碑分化电影，展示其 1 星 vs 5 星评论各 5 条原文对照。
- **分析要点**：同一部电影内文本是否清晰反映评分差异——这是控制"电影本身分数"干扰后，文本信号是否存在的最直接证据，也提示模型可能需要"同电影内比较"的评估视角。

## 9. EDA → 建模的关键结论对接

EDA 完成后应能回答以下问题，它们直接决定模型方案（见 `02-rating-model-plan.md`）：

1. RATING 类别不平衡程度 → 是否需要类别权重/重采样；
2. 超短文本占比 → 是否设置最小长度过滤；
3. 分星级区分词是否显著 → 词袋 baseline 是否可望达到可用精度；
4. 时间维度是否存在漂移 → 验证集切分是否需按时间；
5. 重复评论与刷号程度 → 清洗规则。
